Kotlin: Вопросы на собесе (87)
Variables (13)
Разница между val и var?
val используется для создания неизменяемых переменных, значение которых можно установить только один раз, тогда как var создаёт изменяемые переменные, значение которых можно изменять.
Разница между val и const val?
val – обычное неизменяемое свойство, значение вычисляется в рантайме.
const val – константа: значение известно на этапе компиляции, доступно только для примитивов и String, объявляется на верхнем уровне или в object/companion.
В чем преимущество использования val вместо var?
Использование val вместо var обеспечивает неизменяемость, что делает код безопаснее и облегчает его понимание. Это помогает избежать непреднамеренных изменений данных, снижая вероятность ошибок.
Что будет если вызвать lateinit var до объявления?
Произойдет UninitializedPropertyAccessException.
Всегда ли val возвращает одно и тоже значение?
Не всегда. Если добавить get() - значение будет возвращаться каждый раз при обращении к свойству, и оно может изменяться в зависимости от логики геттера.
Для чего используется const?
Для объявления неизменяемых констант, которые известны на этапе компиляции. Могут быть использованы в качестве значений по умолчанию и в аннотациях.
Какие типы данных поддерживает const?
Int Long Double Float Boolean Char String
Можно ли в const добавить List?
Нет. Тип должен быть известен на этапе компиляции и быть неизменяемым.
Где можно объявлять константу?
На уровне файла (top-level) вне классов.
Внутри object.
Где хранятся переменные const val?
const val компилируется в static final поле, а при использовании обычно подставляется в байткод как литерал на месте обращения.
Есть ли в Kotlin возможность объявить поле, чтобы оно скомпилировалось в Java-примитив?
Да: не-nullable числовые типы и Boolean/Char компилируются в Java-примитивы, а nullable-версии компилируются в обёртки.
Каким правилам должна соответствовать переменная, чтобы стать Java-примитивом?
Нужна ненуллабельность и примитивный тип Kotlin. Также значение не должно попадать в контекст, где требуется объект, иначе произойдёт boxing.
Можно ли изменить переменную типа val?
val нельзя переназначить после инициализации, но можно менять состояние объекта, на который она ссылается. Например: val myList = mutableListOf(1, 2, 3); myList.add(4).
Types (2)
Какие типы есть в Kotlin?
Числовые: Int Long Double Float Byte Short
Символы: Char
Логический: Boolean
Строки: String
Специальные: Any Unit Nothing
Почему в Kotlin нет примитивных типов?
Потому что Kotlin строит единую объектную модель типов: все типы выглядят одинаково и поддерживают методы и расширения, а под капотом компилятор использует примитивы там, где это возможно.
Basic Types (7)
Что такое Any?
Базовый тип для всех классов в Kotlin.
Какие методы есть у класса Any?
equals() hashCode() toString()
Разница между Any в Kotlin и Object в Java?
Any – корневой тип Kotlin и минимальный контракт: equals, hashCode, toString.
Object в Java дополнительно содержит мониторные методы wait/notify/notifyAll, поэтому они доступны только на уровне JVM-объектов, а не как часть API Any.
Что такое Unit?
Тип для функций без возвращаемого значения, аналог void в Java.
Для чего нужен Nothing?
Тип, который означает «значения не бывает»: используется для функций, которые не возвращают результат, потому что всегда бросают исключение или не завершаются.
Как устроен Nothing?
Класс с приватным конструктором.
Почему Unit в Kotlin существует в единственном экземпляре?
Потому что Unit представляет «единственное пустое значение». Такое значение не имеет вариантов, оно всегда одно и то же, поэтому и экземпляр один.
Modifiers (7)
Какие есть модификаторы доступа в Kotlin?
public private protected internal
Разница между модификаторами в Kotlin и Java?
В Kotlin internal ограничивает доступ в пределах модуля, а в Java эквивалентный модификатор отсутствует.
Для чего явно используется модификатор final в Kotlin?
Запрещает повторное переопределение метода в дочернем классе.
Для чего используется ключевое слово open?
Используется для того, чтобы разрешить наследование от класса или переопределение метода/свойства, поскольку по умолчанию классы и их члены закрыты для наследования.
Можно ли переопределить функцию без open?
Нет. Без open или abstract переопределение невозможно. Функция считается final.
Можно ли объявить конструкцию private open class Person?
Да.
Какие существуют модификаторы доступа у элементов класса?
public доступен из любого места. Это значение по умолчанию.
private доступен только внутри самого класса или файла (если используется на уровне файла).
protected доступен только внутри самого класса и его подклассов. Не может использоваться для элементов на уровне файла.
internal доступен внутри модуля, то есть коду, который компилируется вместе (например, в одном проекте или библиотеке).
open позволяет методу быть унаследованным или переопределенным. По умолчанию все классы и методы в Kotlin являются final, если не указано иное.
final запрещает наследование класса или переопределение метода. Используется по умолчанию для классов и методов, если не указан модификатор open.
Exceptions (11)
В чем отличие исключений в Kotlin и Java?
В Kotlin нет checked exceptions: компилятор не заставляет объявлять их в сигнатуре и обрабатывать.
Есть ли в Kotlin проверяемые исключения?
Нет, в Kotlin checked exceptions отсутствуют: компилятор не требует ни throws в сигнатуре, ни обязательного try/catch.
Как обрабатываются исключения в Kotlin?
Через try/catch/finally: исключение из try перехватывается подходящим catch, а finally выполняется всегда для очистки ресурсов.
Какая иерархия у исключений в Kotlin?
В Kotlin иерархия исключений основана на классе Throwable, который является корневым классом. Он делится на две основные категории: Error - ошибки, указывающие на серьезные проблемы, с которыми приложение не может справиться (например, OutOfMemoryError). Exception - исключения, которые могут быть обработаны программой: RuntimeException: Исключения времени выполнения, (например, NullPointerException, IndexOutOfBoundsException, IllegalArgumentException) и Checked exceptions: Исключения, которые должны быть обработаны или объявлены в сигнатуре функции (например, IOException).
В чем принципиальная разница между Error и Exception?
Error обозначает серьезные проблемы, обычно вне контроля приложения, тогда как Exception относится к условиям, которые можно предсказать и обработать для повышения устойчивости.
Приведи примеры исключений типа Error в Kotlin?
OutOfMemoryError
StackOverflowError
Для чего в конструкции обработки исключений нужен блок finally?
Блок finally выполняется независимо от того, произошло ли исключение, что позволяет гарантировать выполнение кода, например, для освобождения ресурсов, таких как закрытие потоков или соединений.
Может ли конструкция try-catch-finally не содержать блок try?
Нет.
Может ли конструкция try-catch-finally не содержать блок catch?
Да.
Сколько блоков catch может содержать конструкция try-catch-finally?
Сколько угодно.
Переменной A присвоен блок try-finally, в try значение устанавливается = 10 в finally = 20, чему будет равно А?
Переменная A будет равна 10, поскольку значение в блоке try присваивается переменной до выполнения блока finally. Блок finally выполняется после, но он не изменяет значение переменной A.
init (4)
Сколько блоков init можно объявить в классе?
Сколько угодно.
В каком порядке выполняются код в нескольких блоках init?
В порядке их объявления в классе.
Где код выполнится быстрее, в блоке init или в secondary constructor?
Код выполнится быстрее в блоке init, так как он вызывается сразу после первичного конструктора.
Можно ли объявить блок init внутри object?
Да, блок init можно объявить внутри object, и он выполнится при первой инициализации этого объекта.
Class (6)
Какие классы существуют в Kotlin?
class, data class, value class, sealed class, enum class, inner class, nested class (просто класс внутри класса).
Разница между class в Kotlin и Java?
В Kotlin классы по умолчанию final, в Java - public. Kotlin поддерживает первичные и вторичные конструкторы; Java – только явные. В Kotlin есть data class с автоматической реализацией методов.
Разница между == и ===?
== сравнивает значения (эквивалент equals в Java).
=== сравнивает ссылки (проверяет, указывают ли обе ссылки на один и тот же объект).
Как сравнить ссылки на классы?
С помощью оператора ===. Этот оператор проверяет, ссылаются ли две переменные на один и тот же объект в памяти.
Что выводит метод toString() у обычного класса?
По умолчанию метод toString() у обычного класса в Kotlin выводит строку, состоящую из имени класса и хеша объекта в формате, похожем на: ClassName@hashcode.
Как работает наследование в Kotlin?
Классы по умолчанию final, для наследования базовый класс помечается open или abstract, наследник объявляется через :, переопределяемые члены помечаются open, а в наследнике – override.

Нет.

Functions (7)
Чем отличается передача параметров в функцию в Kotlin и в Java?
Kotlin поддерживает значения по умолчанию для параметров, что позволяет вызывать функции без необходимости указывать все аргументы, в Java для этого требуется перегрузка методов. В Java можно работать с полями функции, присваивая им новые значения в теле функции.
Как в Kotlin передаются параметры функции по ссылке или по значению?
В Kotlin параметры передаются по значению: для объектов передаётся значение ссылки, поэтому можно менять состояние объекта, но нельзя заменить объект у вызывающей стороны.
Если передать в функцию класс с var-полями можно ли будет поменять значение полей?
Да, если передать в функцию объект класса с var-полями, можно изменить значения этих полей, так как объект передается по ссылке.
Что такое функция высшего порядка?
Это функция, которая принимает другую функцию в качестве аргумента или возвращает функцию в качестве результата.
Что такое анонимная функция?
Анонимная функция – это функция без имени, используемая на месте для кратковременных операций.
Как переопределить функцию родительского класса?
В родительском классе функция помечается open или abstract, в наследнике используется override. При необходимости можно вызвать реализацию родителя через super.foo().

Lambdas (3)
Что такое лямбда в Kotlin?
Анонимная функция, которую можно хранить в переменной и передавать как аргумент, при необходимости захватывая переменные из внешней области видимости.
В каком из разделов памяти хранятся лямбды?
Лямбды в Kotlin хранятся в разделе памяти, называемом heap (куча). При создании лямбды для хранения ее состояния и захваченных переменных, создается объект, который размещается в куче.
Есть ли equals и hashcode у лямбды в Kolin?
Есть обе функции.
Анонимный класс (3)
Что такое анонимный класс?
Класс без имени, который объявляют и сразу создают в месте использования, обычно чтобы реализовать интерфейс или переопределить методы базового класса.
Можно ли создать инстанс анонимного класса?
Да, анонимный класс создаётся сразу как объект в момент объявления.
Какой недостаток есть у анонимных классов с точки зрения памяти?
Анонимный класс часто хранит ссылку на внешний объект. Если этот класс живёт долго, он удерживает внешний объект в памяти и это может привести к утечке.
DSL (3)
Что такое DSL в Kotlin?
Это стиль API, который позволяет писать код почти как конфигурацию, делая его более декларативным и читаемым.
Какие есть примеры использования DSL?
Gradle Kotlin DSL. Jetpack Compose. HTML Builders: Создание HTML-документов.
Какие конструкции поддерживает DSL?
Лямбды с приемником: позволяют вызывать функции объекта без явного указания его имени. Инфиксные функции: позволяют писать более читаемые выражения. Расширения: добавляют методы к существующим классам для улучшения API. Именованные аргументы: улучшают читаемость, особенно для сложных вызовов функций. Операторы перегрузки: позволяют использовать синтаксический сахар для улучшения выразительности.

Потому что на JVM это свойство метода: @Synchronized говорит компилятору сгенерировать мониторную синхронизацию для метода, как synchronized в Java.

Другие (12)
Чем Kotlin отличается от Java?
Kotlin предлагает лаконичный синтаксис, поддержку нулевой безопасности, корутины для асинхронного программирования и расширенные функции, такие как свойства и функции расширения, которые отсутствуют в Java. Кроме того, Kotlin полностью совместим с Java и предоставляет современную альтернативу с улучшенной выразительностью и безопасностью. Null-safety. Именованные аргументы. Выведение типов. Extension-функции. Локальные функции. Операторы перегрузки. Data-классы. Sealed-классы. DSL (Domain-Specific Languages).
Из Kotlin можно вызвать Java, а из Java – Kotlin. За счет чего это достигается?
Совместимость достигается общей платформой (JVM), единым бинарным форматом (.class) и специально сгенерированными метаданными/аннотациями, которые «склеивают» две экосистемы во время компиляции и выполнения. Оба языка компилируются в JVM-байткод (.class), поэтому их артефакты взаимно видимы. Kotlin-компилятор генерирует для свойств геттеры/сеттеры, топ-level-функции – статические методы, создаёт перегрузки для default-параметров и встраивает @Nullable/@NotNull. Метаданные @kotlin.Metadata помогают Kotlin-рантайму и плагинам отражения «восстановить» Kotlin-специфику (null-safety, extension-функции и т. п.) при работе с Java-классами.
В чем преимущество Kotlin в Andrid-разработке?
Лаконичный и безопасный код, null-safety, удобные data class и sealed class, extension-функции, корутины для асинхронности и полную совместимость с Java-экосистемой.
Что не нравится в Kotlin?
Высокая функциональность. Избыточное использование scope-функций. Более длительное время компиляции по сравнению с Java.
Что такое null safety в Kotlin? Как осуществить проверку на null?
Null safety предотвращает ошибки с null. Проверку на null можно выполнить с помощью безопасного вызова ?., оператора Элвиса ?: или оператором !! для выброса исключения, если значение null.
Для чего используется аннотация @JvmOverloads?
Генерирует перегруженные версии функций или конструкторов с параметрами по умолчанию для улучшения совместимости с Java-кодом.
Чем if в Kotlin отличается от if в Java?
В Kotlin if является выражением, возвращающим значение, что позволяет использовать его в присваивании.
Зачем нужны Kotlin Contracts?
Kotlin Contracts нужны, чтобы сообщить компилятору дополнительные гарантии о поведении функции, что улучшает анализ кода, особенно smart cast и работу с nullable.

Collections (11)
Kакие типы коллекции существуют в Kotlin?
List MutableList Set MutableSet Map MutableMap
Зачем в Kotlin коллекции делятся на mutable и immutable?
Предотвращается изменение данных при передаче, улучшается предсказуемость и потокобезопасность в многопоточном окружении без дополнительных синхронизаций.
Разница между mutable и immutable коллекциями в Kotlin?
Mutable коллекции позволяют изменять свои элементы, тогда как immutable коллекции не допускают изменений после создания, требуя создания новых экземпляров при модификации.
Во что Mutable-коллекции Kotlin превращаются в Java?
Mutable-коллекции в Kotlin превращаются в стандартные изменяемые коллекции Java. MutableList становится java.util.List. MutableSet превращается в java.util.Set. MutableMap становится java.util.Map.
Как работает функция map для коллекций в Kotlin?
Применяет функцию transform к каждому элементу исходной коллекции и возвращает новую коллекцию.
Какую Map создает mapOf()?
mapOf() создает пустую неизменяемую Map, а mapOf("a" to 1, "b" to 2) обычно создает LinkedHashMap, где порядок элементов сохраняется.
Как получить уникальные объекты из списка?
Использовать оператор distinct(). Этот метод сохраняет порядок элементов и убирает дубликаты.
Как написать свою функцию map для коллекции?
Реализовать через inline fun с циклом for и добавлением результата в mutableListOf.
Какой будет тип и что выведется?
Тип будет List. Вывод: [2+1, 1+2].
Что напечатает println?
[0]
Будет ли работать это код, как исправить?
Код не будет работать корректно, так как нельзя изменять коллекцию во время её итерации – это может привести к пропуску элементов. Исправить можно, используя removeIf.
Sequences (6)
Для чего нужен Sequence?
Для ленивых цепочек операций: элементы обрабатываются по одному по мере запроса результата, что уменьшает промежуточные коллекции и лишние вычисления на больших данных.
Как Sequence работает с точки зрения памяти?
Память экономится за счёт ленивости: цепочка операций не создаёт промежуточные коллекции, элементы проходят через неё по одному, и в памяти удерживаются только текущий элемент и состояние итератора.
Разница между Collection и Sequences?
Collection выполняет операции сразу и часто создаёт промежуточные коллекции. Sequence выполняет операции лениво и прогоняет элементы через цепочку по одному, без промежуточных коллекций.
В каких случаях Sequence лучше Collections?
Когда есть длинная цепочка операций над большой коллекцией, или результат нужен частично, и важно не создавать промежуточные коллекции.
Как будут выполняться эти операторы? Как улучшить метод чтобы было меньше накладных расходов?
Сейчас каждый оператор проходит по данным и создаёт промежуточную коллекцию. Уменьшить накладные расходы можно так: начать с asSequence() и в конце вызвать терминальную операцию, чтобы цепочка выполнялась лениво без промежуточных коллекций.
Как сломать Sequence, чтобы он работал некорректно?
Сломать можно нарушив контракт итератора: hasNext() и next() должны быть согласованы, а при отсутствии элементов next() обязан выбросить NoSuchElementException.
Kotlin Generics: Вопросы на собесе (7)
Для чего нужны дженерики в Kotlin?
Дженерики нужны, чтобы писать универсальный код, который работает с разными типами и сохраняет типобезопасность на этапе компиляции, без ручных приведений.
Разница между дженериками в Kotlin и Java?
В Java variance выражают через wildcards, в Kotlin – через out и in, поэтому сигнатуры обычно читаются проще. Ещё Kotlin поддерживает reified-дженерики в inline функциях, а в Java типы всегда стираются.
Как Kotlin решает проблемы со стиранием типов, которые существуют в Java?
Kotlin решает проблему стирания типов с помощью inline-функций и ключевого слова reified, которое сохраняет информацию о типах на этапе выполнения, позволяя выполнять операции с ними внутри функции.
Для чего в дженериках используются in и out?
in контравариантность, тип можно использовать только для входных параметров. Он безопасно заменяется на более специфичный тип.
out ковариантность, тип можно использовать только для возвращаемых значений. Он безопасно заменяется на более общий тип.
Что такое инвариантность, ковариантность и контравариантность?
Инвариантность означает, что типы не могут быть заменены друг другом, даже если они имеют отношения наследования. Ковариантность (out) позволяет использовать подтипы. Контравариантность (in) позволяет использовать супертипы.
Что такое звездная проекция в Kotlin и где она используется?
Звёздная проекция – это «неизвестный параметр типа»: её используют, когда конкретный тип обобщения не важен, но нужно безопасно принимать или передавать значение с неизвестным generic-параметром.
Разница между List<*> и List<Any>?
List<*> – список неизвестного типа, из него безопасно читать только Any?, но нельзя добавлять элементы; List<Any> – список именно Any, допускает добавление значений типа Any.
Kotlin Delegation: Вопросы на собесе (12)
lazy (6)
Для чего используется lazy?
Для отложенной инициализации свойства – значение вычисляется только при первом обращении и затем кешируется.
Какие параметры есть у lazy?
У lazy есть параметр режима потокобезопасности LazyThreadSafetyMode (SYNCHRONIZED, PUBLICATION, NONE) и лямбда-инициализатор, вычисляющий значение.
Какие параметры потокобезопасности LazyThreadSafetyMode есть у lazy?
SYNCHRONIZED – потокобезопасная инициализация с блокировкой, значение вычисляется один раз. PUBLICATION – несколько потоков могут вычислить значение одновременно, но сохранится первое опубликованное. NONE – без синхронизации, небезопасно в многопоточности, подходит только для single-thread сценариев.
На каком потоке исполняется lazy?
Инициализация lazy выполняется на том потоке, который первым обращается к значению.
Что будет если несколько раз вызвать переменную lazy?
Значение вычисляется один раз при первом обращении, затем возвращается закешированный результат без повторного выполнения блока.
Является ли lazy потокобезопасным?
Да, lazy является потокобезопасным по умолчанию, используя LazyThreadSafetyMode.SYNCHRONIZED. Это означает, что при первом доступе к значению инициализация будет безопасной для потоков.
Другие (6)
Для чего нужны делегаты?
Позволяют передать логику хранения, инициализации и реакции на изменения свойства отдельному объекту, уменьшая шаблонный код и переиспользуя поведение.
Какие виды делегатов есть в Kotlin?
На класс и на поле.
Какие стандартные делегаты есть в Kotlin?
lazy() observable() vetoable() notNull() map()
Как работает делегат на класс?
Позволяет делегировать реализацию свойств или методов другому объекту. Для этого нужно использовать ключевое слово by, указывая на делегирующий объект.
Как создать свой собственный делегат?
Реализовать интерфейс ReadOnlyProperty или ReadWriteProperty. Затем необходимо определить методы getValue и (при необходимости) setValue.
Какие проблемы могут возникнуть при использовании делегатов?
Утечки памяти – при использовании by lazy с контекстами Android (например, Activity) легко получить утечку, если делегат живёт дольше, чем контекст. Ошибки в потоках – by lazy по умолчанию не потокобезопасен (LazyThreadSafetyMode.NONE), можно случайно получить гонку. Сложность отладки – делегаты абстрагируют логику, и иногда сложно понять, откуда пришла ошибка.
Kotlin Object: Вопросы на собесе (11)
object (4)
Что такое object?
Ключевое слово для создания анонимных классов и синглтонов, позволяющее создавать экземпляры без явного определения класса.
Варианты использования object в Kotlin?
object и data object - синглтон. companion object. Анонимный класс. Объектное выражение.
Можно ли наследоваться от object?
Нет. Объект является синглтоном, и его нельзя расширять или создавать его подклассы.
Как object выглядит под капотом в Java?
В Kotlin object создаёт синглтон, который под капотом реализуется как статический класс в Java. Он содержит статические методы и свойства, инициализируется при первом обращении.
companion object (7)
Зачем нужен companion object?
Для членов класса, доступных по имени класса без экземпляра: констант, фабричных методов и общих утилит.
Когда инициализируется companion object?
При первом обращении к классу, в котором он объявлен. Это происходит до создания любого экземпляра класса, что делает его доступным для статических вызовов и операций.
Что будет инициализировано первым: companion object или экземпляр класса?
Сначала инициализируется companion object, а затем создаётся экземпляр класса.
Чем является companion object: inner или nested классом?
Является nested классом и не имеет ссылки на экземпляр внешнего класса.
Имеет ли companion object доступ к приватным полям класса в котором объявлен?
Да.
Сколько companion object можно объявить внутри класса?
Один. В Kotlin допускается только один companion object на класс.
Есть ли разница между именованным и безымянным companion object?
Разницы в доступе к методам и свойствам нет – в обоих случаях можно обращаться через имя класса.
Kotlin Data Class: Вопросы на собесе (26)
constructor (4)
Как рекомендуется объявлять переменные в конструкторе data-класса?
Использовать val для неизменяемых полей (код более безопасный и предсказуемый).
Можно ли описать data-класс с пустым конструктором, но с полями внутри класса?
Нет нельзя.
Можно ли создавать вторичные конструкторы в data class?
Да, но они должны вызывать первичный конструктор, чтобы корректно инициализировать все свойства класса.

В data class вторичный конструктор не влияет на генерацию: equals, hashCode, toString, copy и componentN строятся только по свойствам из первичного конструктора.

equals() hashCode() toString()
На основе чего вычисляются методы в data class?

Что произойдет если вызвать метод copy без аргументов?

Результат будет false, так как это два разных объекта в памяти.

Методы componentN автоматически генерируются для data class и возвращают свойства объекта по порядку. Это позволяет удобно извлекать значения, например, при деструктивном присваивании.

Нет.

Лямбда станет частью equals/hashCode/copy: разные экземпляры лямбды обычно не равны, поэтому объекты с одинаковыми данными могут считаться разными и «ломать» сравнение и ключи в хеш-коллекциях.
Как хранить лямбды в data-классе, чтобы объекты корректно сравнивались?
Хранить их вне конструктора, в теле класса. Это исключит их из equals и hashCode, сохраняя корректное сравнение объектов.

Kotlin Value Class: Вопросы на собесе (6)
Для чего нужен value class?
Создает легковесную обертку для значений, обеспечивая безопасность типов и оптимизацию памяти без создания объектов в куче. Это полезно для представления простых значений с дополнительной семантикой.

В обычный примитив (если поле – примитив) или ссылку на объект (если поле – объект). Сам класс исчезает, остаётся только его единственное поле.

Kotlin Sealed Class: Вопросы на собесе (12)
Что такое sealed class?
Это класс с ограниченным набором подклассов. Он позволяет выражать иерархии, где возможные варианты известны на этапе компиляции. Используется для безопасного управления состоянием, например, при обработке событий в when.
Что такое sealed interface?
Интерфейс с ограниченным набором реализаций: компилятор знает всех его наследников, поэтому when по нему может быть исчерпывающим без else.
Преимущества sealed-классов?
Гарантированное исчерпывающее перечисление всех возможных подклассов, что позволяет более безопасно работать с when выражениями. Улучшенная читаемость и контроль над иерархией классов. Ограничение наследования, что делает код более предсказуемым и поддерживаемым.
Какие ограничения наследования есть у sealed class?
Нельзя создавать подклассы вне того файла, где он объявлен.
Можно ли объявлять наследников sealed-класса в разных пакетах или модулях?
Нет, наследники sealed-класса должны находиться в том же пакете и модуле, что и сам sealed-класс.
Разница между sealed class и enum class?
enum class – фиксированный набор заранее созданных констант одного типа (набор состояний). sealed class – закрытая иерархия типов, где каждый вариант может быть отдельным классом со своими полями и логикой (набор значений).
Разница между sealed class и enum class с точки зрения хранения в памяти?
У enum каждый элемент – единственный заранее созданный экземпляр, поэтому все обращения идут к тем же объектам. sealed – это обычные классы в закрытой иерархии, и экземпляры создаются каждый раз при создании конкретного варианта.
Разница между sealed class и abstract class?
sealed class задаёт закрытый список наследников, известный компилятору, поэтому when может быть исчерпывающим. abstract class не ограничивает наследование и используется как базовый тип с общей логикой и абстрактными методами.
Разница между sealed class и sealed interface?
sealed class – закрытая иерархия с общей реализацией и состоянием. sealed interface – закрытый контракт без состояния, который могут реализовать разные классы из разных иерархий.
Разница между sealed interface и interface?
sealed interface ограничивает набор реализаций, и компилятор знает их все. Обычный interface может реализовать кто угодно, поэтому набор реализаций открыт.
Как sealed class выглядит под капотом в Java?
Как abstract class.
Какие классы могут наследоваться от sealed class?
class data class object data object inner class sealed class
Kotlin Inner Class: Вопросы на собесе (6)
Для чего используется inner class?
Позволяет классу получить доступ к свойствам и методам внешнего класса, что удобно для работы с связанными данными и логикой.
Разница между inner и nested классами?
inner class имеет доступ к полям и методам внешнего класса, обычный класс этого не может. Кроме того, inner class создается внутри внешнего класса и связан с его экземпляром, а обычный класс может существовать независимо.
Почему inner-class имеет доступ к полям родительского класса?
Потому что он неявно содержит ссылку на его экземпляр. Это позволяет внутреннему классу обращаться к переменным и методам внешнего класса, как если бы они были его собственными.
Есть ли у inner-класса доступ к приватным полям родительского класса?
Да, через неявную ссылку на его экземпляр.
Есть ли у родительского класса доступ к приватным полям inner-класса?
Нет.
Риски использования inner-классов?
Утечки памяти – inner держит ссылку на внешний класс и может удерживать Activity/Fragment. Продление жизненного цикла – callbacks, корутины, Handler внутри inner не дают внешнему объекту освободиться.

reified (4)
Для чего используется reified?
Используется в обобщённых функциях для сохранения информации о типе во время выполнения, позволяя напрямую работать с типом-параметром, чего обычно нельзя делать из-за стирания типов.
Почему reified можно использовать только с inline-функциями?
Позволяет сохранить типы дженериков, которые обычно стираются во время выполнения.
Почему reified позволяет сохранить тип объекта?
Потому что в inline-функциях код внедряется прямо в место вызова, и благодаря этому типы дженериков не стираются на этапе компиляции.
Зачем нужно сохранять тип в inline-функциях?
Чтобы безопасно делать is T, as T или T::class.
Другие (11)
Что такое-inline функции и зачем они нужны?
inline просит компилятор подставить тело функции в место вызова, чтобы уменьшить стоимость вызова и часто избежать создания лишних объектов для лямбд.
Какие по размеру функции рекомендуется инлайнить?
Маленькие по объёму: содержит минимальное количество инструкций, например, простые математические операции, проверки условий, или короткие выражения.
Для чего используется noinline?
Предотвращает встраивание лямбда-выражений в код, позволяя передавать их как обычные функции.
Для чего используется crossinline?
Предотвращает неявный возврат из лямбда-выражения в inline-функциях через return, обеспечивая корректное управление потоком.
Минусы использования inline-функций? (Когда не стоит инлайнить)
Увеличивается размер байт-кода. Возрастает сложность отладки так как код становится менее читаемым.
Когда нельзя использовать inline?
В рекурсивных функциях. В локальных функциях.
Как понять, что функцию нужно инлайнить?
Инлайн имеет смысл для маленьких часто вызываемых функций, особенно принимающих лямбды: это уменьшает стоимость вызова и часто убирает создание объектов под лямбды.
За счет чего выполняется оптимизация в inline-функциях?
Оптимизация за счёт подстановки тела функции вместо вызова: убирается сам вызов и связанные с ним расходы, а для функций с лямбдами часто не создаются объекты под эти лямбды.
Что такое non-local return?
Это return из лямбды внутри inline-функции, который завершает не лямбду, а внешнюю функцию, где эта лямбда вызвана.
Можно ли вызвать inline-функцию из Java?
Нет, так как она реализуется на уровне вызова в Kotlin-коде, и при компиляции в байткод её тело вставляется в места вызова.
Что будет если заинлайнить все функции в приложении?
Если инлайнить всё подряд, код раздуется: вырастет размер APK/Dex и время компиляции, а выгоды не будет – инлайн оправдан в основном для небольших функций и функций с лямбдами.
Kotlin Infix Functions: Вопросы на собесе (2)
Что такое infix-функции в Kotlin и чем они отличаются от обычных функций?
Это обычная функция, которую можно вызывать в инфиксной форме без точки и скобок.
Пример стандартных infix-функций в Kotlin?
to используется для создания пар, например, 1 to false. plus minus times div для математических операций, например, 5 plus 4.
Kotlin Extension Funtions: Вопросы на собесе (9)
Что такое extension-функции в Kotlin и зачем они нужны?
Добавляют методы к существующим типам без наследования и правки класса: это синтаксический сахар для удобных утилит, улучшает читаемость и делает API «нативным» по вызову.
Как extension-функции выглядят в Java? (работают под капотом)
Становится вызовом статического метода с передачей объекта в качестве первого параметра.
Какие ограничения есть у extension-функций?
Не могут изменить поведение класса. Не могут быть заменены (override). Не могут изменять существующие методы. Не поддерживают полиморфизм. Не могут быть вызваны через super. Не поддерживают доступ к private-методам.
Что будет если сигнатура extension-функции совпадет с внутренней функцией класса?
Вызовется внутренняя функция, компилятор подсветит что имя занято.
В каких случаях extension-функция не развернется в статическую функцию Java?
Если она объявлена внутри класса или внутри другой extension-функции.
Можно ли обращаться к приватным полям класса из extension-функции?
Можно только если extension-функция объявлена внутри класса.
Почему нельзя все функции класса сделать extension?
Потому что extension не видят приватные переменные, не переопределяют методы и не участвуют в полиморфизме.
Какой результат выведет функция main?
Правильный ответ: Иван.
Напиши свою extension-функцию filter?
Реализовать через inline fun с циклом for, проверкой predicate и добавлением подходящих элементов в mutableListOf.
Kotlin Scope Functions: Вопросы на собесе (4)
Какие есть Scope-функции?
let run with apply also
let, run, with, apply, also что это за ключевые слова?
Это функции области видимости (scope functions): оборачивают работу с объектом в лямбду, чтобы писать короче и читаемее; отличаются тем, как доступен объект внутри (this или it) и что возвращается (объект или результат лямбды).
Возвращает ли run значение?
Да, функция run возвращает результат последнего выражения внутри своего блока.
Для чего нужны такое scope-функции в Kotlin?
Чтобы компактно выполнить блок кода «в контексте» объекта: меньше повторов, удобнее читать, можно либо настроить объект, либо получить вычисленный результат.
Kotlin Coroutines: Вопросы на собесе (84)
Обработка ошибок (5)
Как обрабатывать исключения в корутинах?
С помощью try-catch. CoroutineExceptionHandler для необработанных исключений. SupervisorJob для изоляции исключений в дочерних корутинах.
Что нужно учитывать при обработки ошибок через try-catch в корутинах?
В корутинах try-catch ловит исключения только внутри текущей корутины, а CancellationException обычно нельзя перехватывать и скрывать – это сигнал отмены, её нужно пробрасывать дальше.
Если передать CoroutineExceptionHandler в async, как обработается исключение?
Корутина выполнится, исключение будет в Deferred.
Разница в обработке ошибок в launch и async?
launch не отдаёт ошибку наружу – исключение падает в самой корутине; async сохраняет исключение в Deferred и выбросит его при await().
Что произойдет в обоих случаях, на каком этапе будет исключение?
В someFun1 исключение будет при вызове await в объекте Deferred. В someFun2 исключение будет при запуске launch.
Отмена корутин (10)
Как отменить корутину?
Метод cancel().
Как отменить все корутины но не отменить Scope?
Использовать cancelChildren().
Перечисли все способы отменить корутину?
Job.cancel() Job.cancelChildren() Job.cancelAndJoin() Scope.cancel()
Как гарантировано остановить корутину, будет ли достаточно метода cancel?
cancel() лишь помечает корутину отменённой. Она остановится только в точках отмены (suspend) или если код сам проверяет isActive/ensureActive (иначе может продолжать работу). Чтобы гарантированно дождаться завершения, делай cancel + join.
Какое поведение у корутины при вызове метода cancel?
При вызове метода cancel корутина помечается как Cancelled, и её выполнение прекращается при следующем проверке на отмену.
Как корутина понимает что она отменена?
Отмена видна по Job (isActive/isCancelled) и через кооперативные точки, где выбрасывается CancellationException (например, delay, yield или явный ensureActive).
Почему не рекомендуется перехватывать CancellationException?
CancellationException – это нормальный сигнал отмены: если её поймать и не пробросить, корутина может продолжить работу «как ни в чём не бывало», сломать каскад отмены и привести к утечкам/зависаниям.
Как работает кооперативность отмены в корутинах?
Отмена кооперативная: корутина сама завершится в точках приостановки (delay, await, withContext) или при явной проверке (isActive/ensureActive), когда Job.cancel() пометит её отменённой и выбросится CancellationException.
Выполнится ли withContext с аргументом NonCancellable внутри отмененной корутины?
Да. withContext(NonCancellable) выполнит блок даже при отменённой корутине (обычно в finally для освобождения ресурсов). После выхода из блока корутина остаётся отменённой.
Что произойдет при вызове данной функции?
Запустится корутина launch, scope будет сразу же отменен, однако корутина launch продолжит свою работу, через секунду будет выведено «Hello!».
Builders (10)
Как запустить корутину? (Какие существуют билдеры корутин)
С помощью билдеров корутин launch или async.
Разница между launch и async?
launch запускает корутину без результата и возвращает Job. async запускает корутину с результатом и возвращает Deferred, который получают через await().
Что возвращают launch и async?
launch возвращает объект Job. async возвращает объект Deferred.
Как дождаться выполнения launch?
Вызвать job.join() – приостановит текущую корутину, пока launch не завершится.
Как дождаться результата, если 1 из 2 корутин вернула исключение?
Использовать supervisorScope, который позволяет одной задаче завершиться с исключением, не влияя на другие.
Как запустить 2 задачи параллельно?
Использовать launch для обеих задач и дождаться завершения через job1.join() и job2.join().
Как запустить 2 задачи параллельно и дождаться результата?
Использовать async для обеих задач и получить результат через result1.await() + result2.await().
В каком случае выполнение будет параллельным, а в каком последовательным?
sum1 последовательно. sum2 параллельно.
Что выведет функция?
1 3 2 4 - First Async Second Async
Есть ли ошибки в коде и что будет выведено на экран?
printFirst и printSecond должны быть suspend. Будет происходить чередование выводов из обеих функций.
Dispatchers (14)
Что такое диспетчер корутины?
Диспетчер корутины управляет потоком выполнения корутины, определяя, на каком пуле потоков будет выполняться код.
Какие диспетчеры есть у корутин?
Dispatchers.Default Dispatchers.IO Dispatchers.Main Dispatchers.Main.immediate Dispatchers.Unconfined
Для чего используются каждый из диспетчеров?
Dispatchers.Main для работы с UI, обновления интерфейса. Dispatchers.Main.immediate для работы с UI, немедленного обновления интерфейса. Dispatchers.IO для операций ввода-вывода (сеть, файлы). Dispatchers.Default для вычислительно тяжелых задач. Dispatchers.Unconfined выполняет в текущем потоке до первой приостановки, потом переключается в зависимости от возобновления.
Какой объем пула потоков на каждом из диспетчеров?
Dispatchers.Main использует главный поток (UI) без пула потоков. Dispatchers.Main.immediate использует главный поток (UI) без пула потоков. Dispatchers.IO имеет динамический пул потоков, по умолчанию до 64 потоков, расширяется при необходимости для операций ввода-вывода. Dispatchers.Default использует пул потоков, равный количеству доступных ядер процессора. Dispatchers.Unconfined не привязан к какому-либо конкретному пулу потоков, выполняется в текущем потоке до приостановки.
Разница между Dispatchers.Default и Dispatchers.IO?
Dispatchers.Default оптимизирован для CPU-интенсивных задач и использует пул потоков равный количеству доступных ядер процессора. Dispatchers.IO предназначен для I/O операций и имеет динамический пул потоков.
Что произойдет с корутиной при переключении с Dispatchers.Default на Dispatchers.IO?
Корутина продолжит работу на Dispatchers.IO (часто на другом потоке). Это требует переключения контекста, но не создаёт новый поток или новую корутину.
Изменится ли реальный поток выполнения при смене диспетчера через withContext?
Возможно. withContext переключает исполнение на пул выбранного диспетчера; фактический поток может измениться.
Почему в Default можно выполнить только 4 операции одновременно (для 4 ядер), а в IO 64?
Default ограничен числом ядер, потому что он для вычислений. IO рассчитан на задачи, которые часто ждут (файлы, сеть, БД), поэтому пул может расширяться и держать больше потоков, обычно до 64.
Чем Dispatchers.Main отличается от Dispatchers.Main.immediate?
Main всегда постит выполнение в очередь main thread. Main.immediate если ты уже на main thread, выполнит сразу без постинга. Если нет – поведёт себя как Main.
Зачем нужен Dispatchers.Main, если в Android везде используется Dispatchers.Main.immediate?
Для других платформ.
Задача выполняется 1 сек, что выполнится быстрее: 10 тредов в цикле или 10 корутин в Dispatchers.Main?
10 тредов быстрее, потому что в Dispatchers.Main 1 поток.
Что будет если выполнять сетевые запросы на Dispatchers.Default?
Если сетевой код блокирующий, то на Dispatchers.Default он займёт потоки, предназначенные для вычислений – из-за этого просядут другие корутины на Default и общая отзывчивость. Если запросы non-blocking (suspend), разницы почти нет.
Приложение в бэкграунде запускает корутину с Dispatchers.IO, через 10 минут система убивает процесс, возобновится ли корутина при следующем запуске приложения?
Нет. При убийстве процесса выполнение прекращается и автоматически не продолжается после следующего запуска.
На каких диспетчерах выполнится код?
map – выполнится на Dispatchers.IO, так как flowOn устанавливает диспетчер для всех операций до него. filter – выполнится на Dispatchers.Default, так как второй flowOn переключает диспетчер для всех операций до него и после map. single – выполнится на Dispatchers.Main, так как это терминальная операция, и она возвращается к диспетчеру, установленному с помощью withContext(Dispatchers.Main).
Job (4)
Для чего нужен Job?
Управляет временем жизни корутины и позволяет отменить ее выполнение, а также отслеживать ее статус.
Для чего нужен SupervisorJob?
Используется для управления иерархией корутин, позволяя дочерним корутинам завершаться независимо – сбой одной корутины не отменяет остальных.
Какие бывают типы Job?
Job SupervisorJob
Какие методы есть у Job?
start – запускает отложенную Job. cancel – отменяет Job. join – ждёт завершения Job. invokeOnCompletion – колбэк по завершении/отмене. getCancellationException – причина отмены. Расширения: cancelAndJoin – отменить и дождаться завершения. cancelChildren – отменить всех дочерних. ensureActive – бросает CancellationException, если Job не активна.
Scope (6)
Что такое scope в корутинах?
CoroutineScope задаёт контекст и Job для корутин, поэтому управляет их жизненным циклом и общей отменой.
Какие есть стандартные Scope в Android?
lifecycleScope состоит из Dispatchers.Main.immediate + SupervisorJob(). viewModelScope состоит из Dispatchers.Main.immediate + SupervisorJob(). MainScope состоит из Dispatchers.Main + SupervisorJob(). GlobalScope состоит из EmptyCoroutineContext.
Как не отменять корутину если один из ее дочерних элементов вышел из строя?
Использовать supervisorScope.
Разница между coroutineScope и supervisorScope?
coroutineScope при падении одного ребёнка отменяет остальных. supervisorScope изолирует ошибки детей: один упал – остальные продолжают работать.
Как дождаться выполнения всех корутин в scope?
Использовать метод joinAll().
Для чего нужен GlobalScope?
GlobalScope запускает корутины с жизненным циклом всего процесса, без привязки к экрану/слою – поэтому они могут пережить компонент и привести к утечкам и «висящей» работе.
suspend (9)
Для чего нужно ключевое слово suspend?
suspend помечает функцию, которая может приостанавливаться и продолжаться позже, не блокируя поток, поэтому асинхронный код можно писать как обычный последовательный.
Как работает механизм приостановки?
При приостановке корутина не держит поток: она сохраняет своё состояние (точку выполнения и локальные данные) и освобождает поток, а когда результат готов, планировщик возобновляет её с того же места.
Какие ограничения есть у suspend-функций?
Они могут быть вызваны только из другой suspend-функции или внутри корутины.
Во что под капотом разворачивается suspend-функция?
suspend-функция компилятором превращается в state machine: добавляется параметр Continuation, а локальные переменные и «точка продолжения» сохраняются в объекте продолжения, чтобы после паузы продолжить с нужного шага.
Где хранятся значения, вычисленные до приостановки корутины?
В объекте Continuation.
Какие данные хранятся в Continuation?
Состояние корутины, местоположение где была приостановлена. Значения всех локальных переменных, вычисленных до приостановки. Контекст: Специальные данные, такие как диспетчеры потоков или информация об обработке исключений. Ссылка на родительский Continuation.
Что такое стейт-машина корутины?
Это код, в который компилятор превращает suspend: выполнение разбивается на шаги (состояния), номер шага и локальные переменные сохраняются в Continuation, а при resumeWith корутина продолжает с нужного состояния.
Чем стейт-машина suspend-функции отличается от других стейт-машин?
Стейт-машина suspend отличается тем, что на точке приостановки она завершает текущий вызов, сохранив шаг и данные в Continuation. Позже её заново «вызовут» через resumeWith, и она продолжит с сохранённого шага, не удерживая поток во время ожидания.
Можно ли вызвать suspend-функцию из Java-кода?
Напрямую нет, но можно обернуть ее в runBlocking и таким образом вызвать.
Синхронизация (5)
Какие есть способы синхронизировать корутины?
Mutex блокирует доступ к разделяемому ресурсу. Channels обеспечивают безопасную передачу данных между корутинами, предотвращая гонки данных. Dispatchers.limitedParallelism(1) сделать 1 поток. Atomic безопасное обновление значений в многопоточной среде без блокировок.
Почему synchronized не будет работать в корутинах?
Потому что он блокирует поток, а корутины работают асинхронно и могут сменять потоки во время выполнения.
Что будет если внутри synchronized вызвать suspend-функцию?
Вызов suspend-функции внутри synchronized блокирует поток, что нарушает асинхронность корутин и может вызвать дедлоки.
Какие проблемы могут возникнуть в корутинах при использовании ReentrantLock?
Использование ReentrantLock может привести к взаимной блокировке, проблемам с производительностью и усложнению отладки, так как блокировки задерживают выполнение, ожидающее освобождения ресурсов.
Что такое Mutex?
Объект для синхронизации корутин, который гарантирует, что только одна корутина может получить доступ к ресурсу в один момент времени.
delay (2)
Как delay работает под капотом?
delay не блокирует поток: он приостанавливает корутину и планирует её возобновление через таймер диспетчера. Когда время истекает, корутина ставится обратно в очередь выполнения и продолжает работу.
Чем Thread.sleep отличается от delay?
Thread.sleep блокирует текущий поток, тогда как delay приостанавливает выполнение корутины.
Context (4)
Что такое контекст корутины?
Контекст корутины представляет собой набор параметров, которые определяют поведение корутины.
Разница между Coroutine Context и Coroutine Scope?
CoroutineContext хранит информацию о корутине (диспетчер, job и т.д.), а CoroutineScope объединяет CoroutineContext и управляет жизненным циклом корутин, запущенных в этом контексте.
Из чего состоит контекст корутины?
CoroutineDispatcher - определяет поток или диспетчер, на котором будет выполняться корутина. CoroutineName - устанавливает имя для отладки. CoroutineExceptionHandler - для обработки исключений. Job - управляет жизненным циклом корутины. SupervisorJob - обеспечить более гибкое управление ошибками и отменой корутин.
Как переключить контекст выполнения корутины?
Через withContext.
Другие (16)
Для чего нужны корутины?
Корутины позволяют писать асинхронный код как последовательный и при этом не блокировать поток, упрощая фоновые задачи, отмену и обработку ошибок.
Основные компоненты корутин?
CoroutineContext CoroutineScope Dispatcher Job Deferred
Как в корутинах работает структурированный параллелизм (structure concurrency)?
Корутины привязаны к scope: пока scope жив, его дочерние корутины управляются вместе и должны завершиться (или быть отменены) до завершения scope.
Как в корутинах работает backpressure?
Backpressure – когда производитель подстраивается под потребителя: send/emit могут приостановиться, а buffer/conflate/collectLatest задают, копить значения или пропускать/заменять их.
Разница между RxJava и Coroutines?
RxJava – реактивные потоки и операторы, управление через подписки (Disposable). Coroutines – suspend/Flow и последовательный стиль, отмена через Job и CoroutineScope.
Чем корутины отличаются от обычных потоков?
Корутины – запускаются поверх потоков и при ожидании приостанавливаются, освобождая поток. Потоки – отдельные единицы выполнения ОС и при ожидании обычно блокируются.
Что занимает больше ресурсов: поток или корутина?
Больше ресурсов занимает поток: у него свой стек и он управляется ОС. Корутина обычно требует меньше памяти и выполняется поверх небольшого числа потоков.
Как в корутинах отправить Single Event?
Использовать Channel или SharedFlow с настройками replay в 0.
Может ли корутина продолжить свое выполнение на другом потоке?
Да, это достигается с помощью контекстов корутин, которые позволяют переключать контексты и тем самым изменять поток выполнения.
За счет чего в корутинах можно писать параллельный код?
Параллельность дают диспетчеры: они запускают корутины на пуле потоков (Default/IO), поэтому разные корутины могут выполняться одновременно на разных ядрах.
Что работает быстрее RxJava или корутины?
Корутины работают быстрее, чем RxJava, в большинстве случаев: корутины легче по памяти и создаются быстрее (нет обёрток Observable/Flowable и подписок); переключение контекста у корутин дешевле (не нужен планировщик, как у RxJava); легче обработка событий и ошибок.
Можно ли внутри корутины запустить этот код?
Да, в корутине можно использовать try-catch для обработки исключений, возникающих при вызове suspend функций.
Будет ли такой код работать?
Да, но есть проблема: корутина, запущенная в scope, продолжит выполняться даже после уничтожения MainActivity, что приведет к утечке памяти. Чтобы этого избежать, нужно связать CoroutineScope с жизненным циклом Activity. Для этого лучше использовать lifecycleScope, который автоматически отменяет корутины при уничтожении Activity.
Какой результат выведется в консоль?
Через 2 секунды первая корутина завершится с исключением, что приведёт к отмене второй корутины.
Что будет выведено в println?
ACBD
Что будет выведено в println?
A0A1CBD. Корутина выводит «A0», «A1», затем «C», отменяется, выводит «B» в finally, и завершается с «D».
Kotlin Flow: Вопросы на собесе (17)
Operators (6)
Какие есть типы функций над потоками?
Функции над Flow делятся на два типа: Терминальные – запускают выполнение и дают результат, обычно suspend: collect, toList, first, last, single, count, reduce, fold. Промежуточные – возвращают новый Flow и цепляются друг за другом: map, filter, take, drop, onEach, combine, zip, transform.
С какими операторами Flow работал?
combine debounce filter flatMapLatest
Как работает оператор flowOn?
flowOn переключает CoroutineContext для верхней части Flow (до него): эмиссия и операторы выше выполняются на указанном диспетчере, а collect и операторы ниже остаются в текущем контексте.
Как работает оператор collect?
collect запускает сбор Flow: подписывается на поток и последовательно обрабатывает каждое значение в лямбде. Это suspend-вызов, поэтому работает внутри корутины и завершается вместе с завершением Flow или отменой.
Какие есть способы объединить 2 источника данных в Flow?
combine объединяет последние значения из двух Flow и эмитит пары значений, когда один из них обновляется. zip объединяет Flow, эмитируя пары значений, только когда оба источника испускают новые значения одновременно.
Новый подписчик должен получать значение сразу, что использовать StateFlow или SharedFlow?
StateFlow: новый подписчик сразу получает текущее значение. SharedFlow – только если настроить replay ≥ 1.
Другие (11)
Для чего применяется Flow?
Flow нужен для работы с асинхронной последовательностью значений во времени: он эмитит данные по мере появления, поддерживает операторы обработки и отмену.
Какие бывают виды Flow?
Flow StateFlow SharedFlow
Как можно создавать Flow и какие есть билдеры?
flow эмитирует значения внутри корутины. flowOf создает Flow из заранее заданных значений. asFlow преобразует коллекции или последовательности в Flow. channelFlow использует Channel для асинхронной эмиссии значений. callbackFlow создает Flow который работает с коллбэками.
Какие операторы есть у Flow?
combine filter debounce transform zip
Какие источники Flow считаются горячими?
StateFlow и SharedFlow
Разница между холодным и горячим потоками в Kotlin?
Холодный поток (Flow) начинает эмитить заново для каждого подписчика и только при сборе. Горячий (StateFlow/SharedFlow) живёт сам по себе и раздаёт значения всем подписчикам, даже если они подключаются позже.
Как из холодного потока сделать горячий?
Использовать операторы stateIn и shareIn.
Разница между StateFlow и SharedFlow?
StateFlow хранит текущее значение и всегда возвращает последнее значение новым подписчикам, обеспечивая сохранение состояния. SharedFlow не сохраняет состояние, а просто транслирует эмитированные значения всем подписчикам, без сохранения их в истории.
Как обрабатывать ошибки в Flow?
catch перехватывает исключения и позволяет выполнить альтернативные действия. onCompletion выполняет действия при завершении потока, независимо от результата. retry позволяет повторить операции в случае ошибки.
Для чего используется SharedFlow?
Чтобы один источник рассылал события/значения нескольким подписчикам, с возможностью replay последних значений и буферизации.
Какие параметры есть у SharedFlow?
replay количество последних значений, которые будут доступны новым подписчикам. extraBufferCapacity количество дополнительных значений, которые могут быть помещены в буфер, когда все подписчики заняты. Это позволяет уменьшить количество пропущенных значений при высокой нагрузке. onBufferOverflow поведение при переполнении буфера. Удалять старые значения при добавлении новых (BufferOverflow.DROP_OLDEST) или новые ждут пока буфер освободится (BufferOverflow.SUSPEND).
Kotlin Channels: Вопросы на собесе (8)
Для чего нужны каналы в Kotlin?
Чтобы передавать значения между корутинами как сообщения: одна корутина отправляет, другая получает, что упрощает координацию и безопасный обмен данными без разделяемого состояния.
Какие есть типы Channel?
Rendezvous Channel Buffered Channel Conflated Channel
Как использовать Channel для реализации паттерна Producer-Consumer?
Создайте канал. Запустите корутину Producer, использующую send для отправки данных. Запустите корутину Consumer, использующую receive для получения данных.
Разница между BufferedChannel и обычным Channel?
BufferedChannel имеет фиксированный размер буфера и может накапливать сообщения, позволяя отправителю продолжать работу, даже если потребитель временно не готов получать данные. Обычный (Rendezvous) Channel требует одновременной готовности отправителя и получателя, не позволяя буферизовать сообщения.
Разница между методами send и offer?
send блокирует выполнение, если канал заполнен, пока не появится место. offer возвращает true, если сообщение успешно отправлено, и false, если канал заполнен, не блокируя выполнение.
Разница между методами receiveAsFlow и consumeAsFlow?
receiveAsFlow преобразует канал в Flow, не закрывая его, что позволяет продолжать отправку данных. consumeAsFlow также преобразует канал в Flow, но закрывает его после завершения, предотвращая дальнейшую отправку данных.
Одна корутина посылает значение в Channel, у которого есть несколько получателей Flow. Все ли они получат значение?
Нет, только один из Flow-ресиверов получит значение из Channel, так как он работает в режиме очереди, и каждое сообщение потребляется одним получателем.
Как сделать Single Live Event для UI событий?
Использовать Channel.
KMP: Вопросы на собесе (40)
Как интегрировать Kotlin Multiplatform в существующий проект?
Добавьте Kotlin Multiplatform Plugin в build.gradle. Настройте общие и платформенные модули (commonMain androidMain iosMain). Обновите сборочные настройки для подключения новых модулей.
Когда использовать expect / actual, а когда реализацию через интерфейс?
Используйте expect/actual для платформо-специфичных реализаций одного API. Интерфейсы применяйте для обеспечения единообразного поведения при одинаковой реализации на всех платформах.
Какие лучшие практики для common-модуля?
Разделяйте код на небольшие, переиспользуемые компоненты. Используйте expect/actual для платформо-специфичных функций. Избегайте зависимости от платформенных библиотек.
Разница между KMP и Kotlin Native?
Kotlin Multiplatform (KMP) позволяет писать общий код для различных платформ (Android, iOS, JS и др.), поддерживая совместное использование логики, но требует платформенных реализаций. Kotlin Native – это часть KMP, обеспечивающая компиляцию кода в нативный код для платформ, таких как iOS, без необходимости использования JVM.
Какие таргеты для iOS обычно выделяют в KMP-проекте?
Обычно используют три таргета: iosArm64 – реальные девайсы, iosX64 – симулятор на Intel Mac, iosSimulatorArm64 – симулятор на Apple Silicon.
Какие трудности возникают при интеграции общего KMP-кода в iOS-приложение через Swift?
Сборка и подключение фреймворка: настройка XCFramework, SPM/CocoaPods, синхронизация версий Gradle и Xcode. Типы и nullability: маппинг Kotlin-типов в Swift, иногда неудобные сгенерированные API. Асинхронность: обёртка suspend и Flow в async/await, completion handlers или Combine. Память и конкурентность Kotlin/Native: фризинг, общий мутабельный стейт между потоками, неочевидные краши и сложная отладка в Xcode.
Как распространять KMP-библиотеку между разными проектами и какие подходы выбрать?
Как основной вариант – публиковать артефакты в Maven-репозиторий (Artifactory, Nexus, GitHub Packages) и подключать как обычную зависимость. Если проекты развиваются в одном монорепо – использовать composite build / включение модулей по source (без публикации). Для iOS-части – собирать XCFramework и раздавать его через SPM (Swift Package Manager) или CocoaPods, чтобы iOS-команда видела библиотеку в привычном виде.
Какие модули выделить при миграции на KMP и как разделить бизнес-логику, платформенный слой и UI?
Общий shared-слой – commonMain с бизнес-логикой: модели, use-cases, интерфейсы репозиториев, общие ошибки. Платформенный код – androidMain / iosMain с реализациями интерфейсов, доступом к БД, сети, хранилищам. UI оставить нативным – androidApp (Compose/View) и iOS-приложение (SwiftUI/UIKit), которые дергают фасад из shared и не знают деталей реализации данных.
Какие недостатки есть в текущей Android-архитектуре?
Бизнес-логика размазана между ViewModel и Repository, нет явного domain-слоя. Activity часто знает слишком много. Сложно переиспользовать и тестировать логику и переносить её в KMP.
Что будет, если в общем KMP-модуле использовать Android-специфичные сущности (Context, Color, LiveData, Date)?
Общий commonMain просто не соберётся под iOS/desktop – компилятор не найдёт этих типов, код станет по факту только Android-кодом. Общая логика «прилипнет» к платформе – её нельзя будет переиспользовать, тестировать и разворачивать на других таргетах без жёстких заглушек.
Какие части проекта не вынести в KMP без адаптации?
UI – всё, что завязано на Android View/Compose для Android, Fragment/Activity, SwiftUI/UIKit, нативную навигацию и lifecycle. Платформенные API – Context, Intent, SharedPreferences, уведомления, permissions, сенсоры, системные сервисы, Keychain и т.п. Библиотеки без multiplatform-поддержки – SDK аналитики, платежей, пушей, БД и всё, что жёстко заточено под JVM/Android или iOS, их нужно оборачивать в интерфейсы и реализовывать на платформах.
Как сделать базу данных мультиплатформенной, чтобы она работала и на iOS, и на Android?
Выделить в commonMain интерфейсы репозиториев и DAO, чтобы общий код знал только про абстракции, а не про конкретную БД. Перейти на мультиплатформенное решение – Room или SQLDelight: общая схема и запросы, разные драйверы под Android и iOS. Платформенные детали инициализации БД (путь к файлу, шифрование, миграции) вынести в androidMain / iosMain и пробрасывать в общий код через конструкторы или DI.
Что выбрать для хранения данных в KMP и почему?
Room – аннотационный подход, при этом получать одну модель и один слой данных для Android и iOS. SQLDelight – даёт строго типизированные модели и запросы из SQL-схемы, хорошо интегрируется с KMP и даёт тонкий контроль над SQL. DataStore – подходит для реактивного key–value и простых конфигов, поддерживает Flow/корутины. Multiplatform Settings – удобен для простого key–value-хранилища (настройки, флаги), единый API поверх SharedPreferences и NSUserDefaults.
Какой DI-фреймворк оптимален для KMP и почему?
Koin – у него есть официальная поддержка KMP, простой DSL и он одинаково работает на Android и iOS.
Чем DI с кодогенерацией отличается от DI без неё и почему это важно в KMP?
DI с кодогенерацией – граф зависимостей проверяется на этапе компиляции, генерируются готовые фабрики/компоненты, меньше оверхеда в рантайме, но нужен KSP и поддержка каждого таргета, что в KMP часто ломает common-код и усложняет сборку. DI без кодогенерации – зависимости собираются вручную или через рантайм-контейнер (Koin, сервис-локаторы), меньше проблем с мультиплатформенной компиляцией, проще поддерживать все таргеты, но меньше compile-time гарантий. В KMP это важно, потому что не все инструменты кодогенерации умеют Native/JS/Wasm – часто безопаснее и стабильнее опираться на ручной DI или фреймворки без тяжёлой кодогенерации в общем модуле.
Чем заменить Retrofit в KMP?
Основной вариант – Ktor Client: мультиплатформенный HTTP-клиент, работает на Android и iOS, есть плагины ретраев, логирования, таймаутов. Для JSON – kotlinx.serialization, даёт типобезопасные модели и общий код сериализации.
Как настроить общие ViewModel в KMP, если UI на iOS остаётся нативным, а на Android – Compose/XML, чтобы жизненный цикл согласовывался на обеих платформах?
Сделать общую SharedViewModel в commonMain без привязки к Android lifecycle – внутри только стейт, Flow/StateFlow и CoroutineScope. На Android оборачивать её в AndroidViewModel/ViewModel, пробрасывая scope из viewModelScope и вызывать clear() у shared-части из onCleared(). На iOS создать wrapper (например IosViewModel), который держит ссылку на SharedViewModel и вручную вызывает start()/stop()/clear() из viewWillAppear / viewDidDisappear или onDisappear в SwiftUI. Общий код опирается только на свои методы (start, clear, observeState), а привязка к жизненному циклу полностью реализуется на каждой платформе отдельно.
Как связать жизненный цикл SwiftUI/UIViewController с жизненным циклом ViewModel?
В общем KMP-коде у ViewModel завести методы вроде onAppear(), onDisappear(), clear() – без зависимостей от UIKit/SwiftUI. В UIViewController вызывать vm.onAppear() из viewWillAppear, vm.onDisappear() из viewDidDisappear, vm.clear() из deinit или момента уничтожения экрана. В SwiftUI дергать vm.onAppear() / vm.onDisappear() через модификаторы .onAppear / .onDisappear или task {} + .onDisappear. Подписки на Flow/StateFlow запускать в onAppear и отменять в onDisappear, чтобы не было утечек и работы в фоне, когда экран уже закрыт.
Как организовать форматирование данных (дат, сумм, цветов, ресурсов), чтобы UI-логика не попадала в общий модуль?
В commonMain хранить только «сырые» значения и семантику – timestamp/LocalDate, сумма в минимальных единицах + currencyCode, enum для цвета/строки/иконки, без Android/iOS-классов. Сделать в платформах мапперы Domain → UiModel, где уже использовать DateFormatter / NumberFormatter / Color / ресурсы и т.п. Если нужен общий контракт – завести интерфейсы DateFormatter, MoneyFormatter и т.д. в commonMain, а реализации для Android/iOS инжектить из платформенного слоя.
Почему хранение UI-логики (строк и цветов) в модели данных – плохая практика?
Потому что это ломает разделение слоёв и сильно снижает гибкость. Модель перестаёт быть «чистой» – в ней появляются строки, цвета и другие детали конкретного UI. Сложно переиспользовать один и тот же домен в разных интерфейсах – Android, iOS, веб, разные темы/языки. Любая правка дизайна или локализации требует изменений в моделях и общем коде вместо изолированного UI-слоя. Тестировать становится труднее – доменные тесты начинают зависеть от текстов и цветов, которые вообще не относятся к бизнес-логике.
Какие зависимости стоит выносить в общий код через expect/actual, а какие – через DI?
Через expect/actual обычно выносят низкоуровневые платформенные примитивы, а через DI – всё, что может меняться и подменяться. expect/actual – системное время, платформа, пути к файлам, storage, логгер. DI – репозитории, API-клиенты, кеш, аналитика, фичи/флаги, любые сервисы, где нужны моки.
Какие ограничения есть у механизма expect/actual в KMP?
Декларации expect не могут содержать реализацию – только сигнатуру, реализация всегда в actual. actual обязан строго совпадать по сигнатуре с expect – типы, generics, suspend, visibility, inline и т.п. Механизм работает на этапе компиляции – нельзя переключать реализации в рантайме.
Как передавать Android Context или iOS-специфичные объекты в общий модуль?
В commonMain описывать интерфейсы, которые нужны общему коду. В androidMain / iosMain делать реализации этих интерфейсов, принимающие Context / iOS-объекты в конструктор.
Какие лучшие практики есть для организации платформенных реализаций?
Держать интерфейсы и бизнес-логику в commonMain, а платформенные реализации класть в androidMain / iosMain. Строить composition root на каждой платформе – там собирать реализации (с Context, iOS-API, SDK) и передавать уже готовые зависимости в общий код. Не использовать Android/iOS-типы в сигнатурах общего кода – только свои интерфейсы и multiplatform-типы. Стараться, чтобы платформенные реализации были максимально тонкими адаптерами, вся логика оставалась в commonMain.
Какие проблемы есть в текущем Objective-C Interop?
Неудобные API на стороне Swift – сгенерированные ObjC-интерфейсы теряют многие Swift-фичи (generics, value-типы, красивые сигнатуры), имена методов часто громоздкие. Ограничения типов – Kotlin generics, sealed-классы, nullable-типизация и коллекции не всегда естественно маппятся в ObjC/Swift, приходится городить обёртки. Асинхронность – suspend/Flow наружу видны как callbacks/объекты-обёртки, нет прямого async/await-опыта, требуется дополнительный слой адаптеров. Отладка и ошибки – стек-трейсы и исключения из Kotlin/Native в ObjC/Swift выглядят непривычно, сложнее локализовать проблему и связать её с исходным Kotlin-кодом.
Как преобразовать Kotlin enum в Swift enum?
Напрямую Kotlin enum не станет нативным Swift enum – его нужно обернуть и промаппить. В interop Kotlin enum выглядит для Swift как класс с набором статических инстансов, а не как нативный Swift enum, поэтому использовать его «как есть» неудобно. На Kotlin-стороне имеет смысл задать стабильный идентификатор для значения – name, ordinal, val code: String или val id: Int. На Swift-стороне объявляется свой enum MyEnum: String/Int с теми же кодами в rawValue. Далее пишется инициализатор или маппер, внутри switch по kotlin.name/code и маппинг в соответствующий кейс, с запасным .unknown на случай новых значений.
Как исправить ситуацию, когда generic из Kotlin становится nullable в Swift?
Ввести ненулевой upper bound у типа – объявлять class Box<T : Any> вместо class Box<T> и по возможности избегать T? в публичных API. На границе с iOS минимизировать generics – выносить в отдельные не-generic DTO/фасады, которые экспонируются в Swift с конкретными типами без лишней nullable-ности. В Swift явно разворачивать типы и добавлять обёртки. Проектировать публичный API KMP так, чтобы generic-и не «торчали» наружу в interop, а оставались внутри общего слоя.
Когда нужна обёртка для Flow, чтобы корректно использовать его из Swift?
Когда Flow нужно отдать прямо в Swift – Swift не умеет «родной» Flow, поэтому его оборачивают в API с callbacks или async/await-подпиской. Когда важен контроль жизненного цикла – обёртка создаёт scope, старт/стоп подписки и отмену, которые можно вызывать из onAppear / onDisappear или lifecycle UIViewController. Когда нужно адаптировать ошибки и типы – обёртка маппит значения Flow и исключения в удобные для Swift модели (Result, свои sealed-like enum). Когда хочется спрятать корутины – Swift-слой видит простой subscribe или for await по асинхронной последовательности, а вся корутинная кухня остаётся в KMP.
Какие ограничения есть у suspend в Swift и как правильно передавать completion-callbacks?
В Swift suspend выглядит как метод с последним параметром–completion, без нативного async/await, если не использовать обёртки. Completion нужно вызывать ровно один раз и на нужном потоке (обычно main), ошибки передавать явно через Result или параметр ошибки. Для удобства лучше поверх делать Swift-обёртки с async/await или использовать KMP-NativeCoroutines, а completion оставить внутренней деталью.
Что такое Swift Export и какие задачи он решает по сравнению с обычным interop?
Swift Export – это механизм, который генерирует нативный Swift-API поверх KMP, без ObjC-обёрток. Он даёт более «свифтовые» типы и сигнатуры – нормальные имена, nullable-ность, generics, вместо громоздких ObjC-интерфейсов. В итоге iOS-команда получает удобный, естественный для Swift DX и меньше пишет ручных обёрток вокруг KMP-кода.
Как подключать стороннюю iOS-библиотеку через cinterop?
Ориентироваться на C/Objective-C API – Swift-библиотеку обычно нужно обернуть в ObjC или использовать её ObjC-часть. Создать .def-файл для cinterop – указать заголовки, compilerOpts и linkerOpts для фреймворка/SDK. В Gradle в iosMain настроить cinterops. Собрать проект – Kotlin/Native сгенерирует Kotlin-обёртки, после чего библиотеку можно вызывать из общего или iOS-кода как обычные Kotlin-функции и типы.
Как Kotlin-код получает доступ к Objective-C API?
Через Objective-C interop в Kotlin/Native – компилятор читает заголовки .h/фреймворки и генерирует Kotlin-обёртки поверх ObjC-типов и методов. Для системных фреймворков Apple обёртки уже сгенерированы и доступны как platform.* модули. Для сторонних SDK на ObjC настраивается cinterop с .def-файлом, после чего Kotlin видит классы/методы как обычные Kotlin-типы и может вызывать их напрямую.
В чём разница между статическим и динамическим iOS-фреймворком?
Статический фреймворк – его код вшивается в бинарь на этапе линковки, не загружается отдельно в рантайме, проще настроить, обычно его используют для KMP XCFramework. Динамический фреймворк – это отдельная библиотека, которую система подгружает при запуске, даёт переиспользование, но сложнее в настройке и добавляет оверхед на загрузку.
Зачем нужен XCFramework и какие проблемы он решает?
Позволяет упаковать в один артефакт несколько вариантов фреймворка, не собирая и не подключая их по отдельности. Избавляет от «fat binary» и ручного склеивания архитектур – Xcode сам выбирает нужный срез для устройства или симулятора. Упрощает распространение KMP-библиотеки на iOS – один XCFramework удобно подключать через SPM/CocoaPods без отдельной логистики по архитектурам.
Чем компиляция JVM отличается от Kotlin/Native на уровнях фронтенда и бэкенда?
На фронтенде используется один и тот же Kotlin-компилятор – парсер, анализ типов и общая IR в целом совпадают. На бэкенде для JVM IR превращается в байткод JVM, который работает поверх JVM-рантайма, её GC и reflection. Для Kotlin/Native бэкенд транслирует IR в LLVM IR и дальше в нативный машинный код без JVM, с другим рантаймом, своим управлением памятью и ограничениями interop.
Что такое FIR/IR и какую роль они играют при компиляции в Native?
FIR – это front-end промежуточное представление Kotlin-кода, на котором выполняются парсинг, проверка типов, анализ и общие для всех таргетов оптимизации. IR – это более низкоуровневое промежуточное представление, единое для разных бэкендов, из которого уже генерируется платформенный код. В Kotlin/Native IR дальше переводится в LLVM IR и затем в машинный код, поэтому все front-end-решения и оптимизации на IR напрямую влияют на итоговый нативный бинарь.
Чем память Kotlin/Native отличается от JVM GC и iOS ARC?
На JVM – классический GC, который сам собирает мусор, двигает объекты и даёт «толстый» рантайм. На iOS – ARC, счётчики ссылок, нет перемещения объектов, нужно следить за циклами и weak/unowned. В Kotlin/Native – свой нативный рантайм и GC без JVM, другой heap, свои правила interop и многопоточности, поэтому поведение по паузам и утечкам отличается от обоих миров.
Как решается проблема циклических ссылок между объектами Kotlin и Swift/Objective-C?
На стороне Swift/Objective-C использовать weak/unowned для ссылок на Kotlin-объекты в полях и замыканиях, особенно если Kotlin-объект держит обратно ссылку на Swift. На стороне Kotlin не хранить долгоживущие сильные ссылки на Swift/ObjC-объекты во «всегда живых» синглтонах/Scope, разрывать цепочку в close/clear. В колбэках и Flow-обёртках явно продумывать владельца и при необходимости вводить отдельные «owner»/dispose() для ручного разрыва цикла.
Какие риски возникают при смешении моделей GC и ARC в одном приложении?
Разные модели времени жизни – проще получить утечки, когда GC-объекты и ARC-объекты держат друг друга. Retain-циклы на границе Kotlin ↔ Swift/ObjC – ни GC, ни ARC не видят полный граф и не могут его разобрать. Сложная отладка и непредсказуемые фризы – профилировщики разделены по мирам, стоп-паузы GC накладываются на работу ARC.
Какие стратегии работы с памятью рекомендуются при interop?
Чётко задавать владение – кто «главный» владелец объекта и кто должен разрывать связи. На Swift/ObjC-стороне использовать weak/unowned для ссылок на Kotlin-объекты в полях и замыканиях. На Kotlin-стороне не держать долгоживущие сильные ссылки на Swift/ObjC-объекты в синглтонах и глобальных scope. Для колбэков и Flow вводить обёртки с явной отменой, вызывать их из lifecycle. Регулярно проверять утечки инструментами профилирования на обеих сторонах.
Android Architecture: Вопросы на собесе (71)
Clean (9)
Что такое чистая архитектура?
Это подход к проектированию программного обеспечения, который разделяет код на слои, минимизируя зависимость между ними. Это позволяет повысить тестируемость, гибкость и поддержку приложения, отделяя бизнес-логику от пользовательского интерфейса и инфраструктуры.
Перечисли слои чистой архитектуры в контексте Android?
Presentation UI и логика представления (Activity, Fragment, ViewModel). Domain Бизнес-логика и правила (UseCase, Interactor). Data Работа с данными (репозитории, источники данных, API).
Какие модули в Clean являются верхними и нижними?
Верхние модули: Presentation (UI, ViewModels) и Domain (Use Cases, Entities), которые отвечают за бизнес-логику. Нижние модули: Data (репозитории, источники данных) и Infrastructure (внешние сервисы, базы данных), которые взаимодействуют с внешними системами и обеспечивают хранение и доступ к данным.
Что такое Entity в Clean?
Entity в Clean – доменная модель с бизнес-правилами и данными, не зависящая от UI, БД и сети; её используют UseCase.
Где в clean-архитектуре используется принцип Dependency Inversion из SOLID?
В Clean Architecture принцип Dependency Inversion помогает отделить бизнес-логику от деталей реализации, определяя интерфейсы в бизнес-логике и внедряя их реализации через Dependency Injection. Это улучшает гибкость и тестируемость, позволяя легко заменять реализации без изменения бизнес-логики.
Недостатки чистой архитектуры, в каких проектах она не нужна?
В маленьких проектах или прототипах, где важна скорость разработки, а не гибкость и расширяемость. В проектах с очень узким функционалом, где количество логики невелико, и разделение на слои только усложнит архитектуру.
Разница между Domain и Data слоями?
Domain слой отвечает за бизнес-логику приложения и включает в себя модели, сервисы и интерфейсы, а Data слой занимается управлением данными, включая их получение, хранение и передачу, работая с внешними источниками данных, такими как базы данных или API.
От кого зависит слой Domain в чистой архитектуре?
Domain не зависит ни от Data, ни от Presentation – он содержит только бизнес-логику и абстракции.
В каком слое размещается Mapper в Clean?
В domain или data слоях, в зависимости от его назначения: если маппер преобразует данные между слоями data и domain (например, из DTO в Entity), его лучше поместить в domain слой, так как он отвечает за преобразование данных в формат, удобный для бизнес-логики. Если маппер используется для преобразования данных только внутри data слоя, его следует поместить в data слой.
MVVM (6)
Что такое архитектура MVVM?
MVVM делит код на Model (данные/логика), View (UI) и ViewModel (состояние и логика экрана): ViewModel не зависит от View, поэтому UI проще тестировать и переживать пересоздание.
Как в MVVM View получает данные из ViewModel?
Через наблюдаемые объекты Flow или LiveData.
Как MVVM соотносится с Clean Architecture?
Model ↔ Data. View ↔ Presentation. ViewModel ↔ Domain. Model будет в Presentation-слое.
Различие между MVVM и MVP?
В MVVM ViewModel управляет состоянием и данными для View через Flow, в то время как в MVP Presenter обрабатывает действия пользователя и обновляет View напрямую.
На каком слое разместим Mapper?
В Clean на слое Data. В MVVM на ViewModel для UI.
Какие паттерны проектирования реализует MVVM?
Наблюдатель (Observer) – ViewModel отслеживает изменения в Model и уведомляет View об этих изменениях. Команда (Command) – ViewModel обрабатывает действия пользователя через команды, которые затем изменяют состояние Model. Посредник (Mediator) – ViewModel выступает посредником между View и Model, обеспечивая их независимость друг от друга.
MVI (2)
Преимущества MVI?
Преимущества MVI – единый источник истины для состояния и односторонний поток данных, поэтому проще предсказывать поведение, отлаживать и избегать рассинхронизаций UI.
Какой компонент MVI отвечает за определение нового состояния на основе текущего состояния и действия?
Reducer
SOLID (11)
Принципы SOLID?
S - Принцип Единственной Ответственности. Каждый класс или метод должны иметь одну ответственность. O - Принцип Открытости/Закрытости. Классы должны быть открыты для расширения, но закрыты для модификации. L - Принцип Подстановки Лисков. Объекты базового класса должны быть заменимы объектами его подклассов без изменения корректности программы. I - Принцип Разделения Интерфейсов. Интерфейсы должны быть специфичными и не содержать методов, которые не нужны реализациям. D - Принцип Инверсии Зависимостей. Модули высокого уровня не должны зависеть от модулей низкого уровня. Оба типа модулей должны зависеть от абстракций.
Где в Android применяется принцип единственной ответственности (S) из SOLID?
UseCase для выполнения одной конкретной бизнес-задачи.
Где в Android применяется принцип открытости/закрытости (O) из SOLID?
При наследовании компонентов. Например в RecyclerView адаптеры можно расширять, добавляя логику для работы с новыми типами данных, но сам класс RecyclerView.Adapter остается неизменным.
Где в Android применяется принцип подстановки лисков (L) из SOLID?
При создании кастомных View. Можно создать класс, который наследует Button, добавляя собственные методы, при этом все методы базового класса остаются работоспособными.
Где в Android применяется принцип разделения интерфейсов (I) из SOLID?
В репозиториях интерфейсы могут быть разделены по действиям, что предотвращает наличие неиспользуемых методов.
Где в Android применяется принцип инверсии зависимостей из (D) SOLID?
Бизнес-логика обращается к абстракциям репозитория, а сам репозиторий может использовать разные источники данных. Это также упрощает тестирование, позволяя заменять реальные реализации на заглушки.
Где в Android нарушается принцип единственной ответственности (S) из SOLID?
Бизнес-логика в Activity/Fragment. Класс ListView.
Где в Android SDK нарушается принцип подстановки Лисков (L) из SOLID?
SparseArray и HashMap: SparseArray не является полной заменой HashMap, хотя используется для аналогичных целей. AlertDialog и Dialog: AlertDialog предполагается как частный случай Dialog, но часто изменяет поведение Dialog.
Какой принцип SOLID будет нарушен если в MVVM модель будет знать о конкретной реализации ViewModel?
Будет нарушен принцип инверсии зависимостей D (Dependency Inversion). Этот принцип требует, чтобы высокоуровневые модули (ViewModel) не зависели от низкоуровневых модулей (Model).
Какие классы/интерфейсы Android API нарушают принципы SOLID?
AsyncTask нарушает Single Responsibility принцип. Context нарушает Interface Segregation принцип. Handler нарушает Liskov Substitution принцип.
Соответствует ли Activity букве S ил SOLID?
Обычно нет: Activity часто совмещает UI, lifecycle и навигацию, поэтому у неё получается несколько причин для изменений.
ООП (7)
Какие есть принципы ООП?
Инкапсуляция. Полиморфизм. Наследование. Абстракция.
Что такое инкапсуляция?
Сокрытие внутренней реализации объекта и предоставление доступа к его данным только через методы, что защищает состояние объекта от несанкционированных изменений.
Что такое полиморфизм?
Способность объектов разных классов реагировать на одни и те же сообщения по-разному, позволяя использовать интерфейсы и абстрактные классы для создания гибких и расширяемых программных систем.
Что такое наследование?
Возможность создавать новые классы на основе существующих, унаследовав их свойства и методы, что способствует повторному использованию кода и упрощает его поддержку.
Что такое абстракция?
Выделение общих свойств и методов объектов, позволяющее сосредоточиться на важных характеристиках, скрывая детали реализации, что упрощает восприятие и использование системы.
Что такое композиция?
Отношение «имеет», при котором класс включает объекты других классов вместо наследования, чтобы переиспользовать поведение и уменьшить связанность.
Без какого принципа ООП нельзя реализовать абстрактную фабрику и почему?
Без полиморфизма: абстрактная фабрика возвращает объекты через общий интерфейс/базовый класс, чтобы клиент мог использовать разные реализации, не зная конкретных классов.
Patterns (17)
Какие есть виды паттернов?
Порождающие паттерны – отвечают за создание объектов. Структурные паттерны – описывают, как классы и объекты взаимодействуют между собой. Поведенческие паттерны – определяют алгоритмы и потоки управления.
Какие есть антипаттерны?
God Object – один объект или класс берет на себя слишком много ответственности. Spaghetti Code – код с плохой структурой, где зависимости между компонентами запутаны. Golden Hammer – использование одной техники для решения всех задач. Magic Numbers – использование «жестко закодированных» чисел без объяснений.
Расскажи про паттерны банды четырех?
Паттерны банды четырех (GoF) – 23 классических паттерна проектирования. Делятся на три категории: Создающие: Singleton, Factory Method. Структурные: Adapter, Decorator. Поведенческие: Observer, Strategy.
Какие есть поведенческие паттерны?
Наблюдатель (Observer). Команда (Command). Стратегия (Strategy).
Какие есть порождающие паттерны?
Одиночка (Singleton). Фабричный метод (Factory Method). Строитель (Builder).
Какие есть структурные паттерны?
Адаптер (Adapter). Декоратор (Decorator). Фасад (Facade).
Расскажи про паттернт Adapter?
Adapter – структурный паттерн, который «оборачивает» один интерфейс в другой: приводит API существующего класса к виду, который ожидает клиент.
Расскажи про паттерн Bridge?
Bridge – паттерн, который разделяет «что делаем» (абстракцию) и «как делаем» (реализацию) через композицию.
Расскажи про паттерн Builder?
Builder – порождающий паттерн для пошаговой сборки объекта.
Какие примеры паттерна Builder есть в Android?
AlertDialog.Builder NotificationCompat.Builder
Расскажи про паттерн Observer?
Observer – паттерн «один ко многим»: наблюдатели подписываются на субъект и получают уведомления при изменениях.
Расскажи про паттерн Factory method?
Factory Method – порождающий паттерн: базовый класс задаёт метод создания, а подклассы переопределяют его.
Расскажи про паттерн Abstract Factory?
Abstract Factory – порождающий паттерн для создания семейства связанных объектов через общий интерфейс фабрики.
Расскажи про паттерн Chain of Responsebility?
Chain of Responsibility – запрос проходит по цепочке обработчиков, и каждый либо обрабатывает его, либо передаёт дальше.
Расскажи про паттерн Prototype?
Prototype – создание объектов через копирование существующего экземпляра-прототипа.
Расскажи про паттерн Momento?
Memento – паттерн для сохранения «снимка» состояния объекта и последующего восстановления, часто для undo.
Расскажи про паттерн DTO?
Data Transfer Object – простой объект только с данными для передачи между слоями/сервисами, без бизнес-логики.
EventBus (2)
Что такое EventBus?
Подход, где компоненты публикуют события в общий «шлюз», а подписчики их получают, не зная друг о друге напрямую.
Почему EventBus считается антипаттерном?
Он делает зависимости неявными: непонятно, кто шлёт события и кто их обрабатывает, поэтому сложнее отладка, тестирование и контроль жизненного цикла подписок.
Single Activity (2)
Какие есть преимущества у SingleActivity?
Упрощенная навигация. Уменьшение проблем с жизненным циклом.
Какие есть минусы у SingleActivity?
Сложность управления навигацией. Увеличение объема кода. Трудности с восстановлением состояния.
Другие (15)
Что нравится в Android-разработке?
Гибкость работы с архитектурами. Jetpack Compose для построения UI. Поддержка Kotlin и Coroutines.
Что не нравится в Android-разработке?
Фрагментация устройств. Медленное время сборки. Устаревшие библиотеки и технологии.
Какие есть архитектуры в Android?
MVVM MVI MVP
Для чего используется Interactor?
Interactor (use case) инкапсулирует бизнес-операцию: принимает запрос от UI, обращается к репозиториям/сервисам и возвращает результат.
Различие между Interactor и UseCase?
Interactor может включать несколько UseCase, а UseCase описывает отдельные бизнес-сценарии.
Что входит в сигнатуру метода?
Его имя и список параметров (их типы и порядок).
Что такое UDF?
Unidirectional Data Flow – это архитектурный паттерн, при котором данные в приложении передаются и изменяются в одном направлении.
Что такое агрегация?
Это отношение между объектами, где один объект содержит другой, но оба могут существовать независимо друг от друга.
Разница между наследованием и композицией?
Наследование создает иерархию классов с повторным использованием кода через базовый класс, тогда как композиция строит объекты из других объектов, делегируя выполнение задач.
Как понять что код качественно написан?
Читаемость. Структурированность. Тестируемость. Отсутствие дублирования. Эффективность. Документация.
Какие еще бывают принципы проектирования кроме SOLID?
DRY KISS YAGNI
Что такое Trunk Based Development?
Подход, где все работают в одной основной ветке (main/trunk), делая частые маленькие интеграции.
Какие преимущества и недостатки у TBD?
Преимущества: простота, частые интеграции, мелкие PR, единая точка правды, ускоренная доставка. Недостатки: жёсткая дисциплина, риск поломки сборки, сложности с большими фичами, нагрузка на CI, необходимость feature flags.
Какие преимущества у многомодульности в Android?
Ускорение сборки. Улучшение структуры кода. Повторное использование и тестирование. Снижение зависимостей.
Какие недостатки у многомодульности в Android?
Сложность настройки и поддержания. Увеличение времени сборки проекта целиком. Усложнение навигации в коде. Повышенные накладные расходы на кросс-модульное тестирование.

Android Concurrent: Вопросы на собесе (9)
Что такое основной поток (UI Thread) в Android, и какие задачи следует выполнять в этом потоке?
UI thread отвечает за отрисовку и обработку ввода, поэтому в нём делают только UI-работу и короткую логику; сеть, БД и долгие вычисления выносят в фон.
Что такое Handler, и как он взаимодействует с Looper?
Handler постит Message/Runnable в MessageQueue потока. Looper крутит цикл этого потока, достаёт элементы из очереди и передаёт их на выполнение.
Как создать собственный поток с Looper и Handler?
Создайте класс, унаследованный от Thread. В методе run() инициализируйте Looper с помощью Looper.prepare(), создайте Handler и вызовите Looper.loop().
Как работает MessageQueue, и как она взаимодействует с Handler и Looper?
MessageQueue – очередь задач конкретного потока. Handler кладёт туда Message/Runnable, а Looper в этом же потоке в цикле достаёт их по порядку и выполняет.
Как передать данные между потоками через Handler?
Данные передаются вместе с задачей: отправляется Message или Runnable, а получатель читает их в handleMessage() или внутри post на нужном потоке.
Как правильно обработать отложенные и повторяющиеся задачи с помощью Handler?
Для отложенных задач используйте postDelayed(), а для повторяющихся – вызывайте postDelayed() в конце Runnable.
Можно ли выполнить сетевой запрос из главного потока в Android?
Нет, выполнять сетевые запросы из главного потока в Android нельзя, так как это может привести к заморозке интерфейса и вызвать NetworkOnMainThreadException.
Какие есть способы в Android выполнить задачу в фоновом потоке?
Handler и HandlerThread. Executor и ThreadPoolExecutor. Coroutines. WorkManager. JobScheduler. IntentService.
Как гарантированно вызвать метод класса на Main-потоке?
Handler.post runOnUiThread View.post launch(Dispatchers.Main)

Интерфейс для обмена данными между двумя устройствами по сети.

SSL (4)
Что такое SSL pinning?
Проверка, что сертификат или публичный ключ сервера совпадает с «закреплённым» в приложении.
Как SSL pinning работает в Android?
На клиенте хранится «пин» сертификата или публичного ключа, и при TLS-рукопожатии он сравнивается с тем, что прислал сервер.
Что такое MITM?
Man-in-the-Middle – атака, где злоумышленник становится «между» клиентом и сервером.
Какие есть способы защитить приложение от MITM-атак?
Всегда использовать HTTPS/TLS. Certificate Pinning. Network Security Config.
OkHttp (3)
Что такое OkHttp и как его использовать для выполнения сетевых запросов?
HTTP-клиент для Android/Java: OkHttpClient управляет соединениями, Request описывает запрос, Call выполняет его синхронно или асинхронно.
Что под капотом использует OkHttp?
HttpURLConnection.
Какие бывают виды интерсепторов?
Application Interceptor – перехватывает запросы до отправки или после получения ответа. Network Interceptor – работает на уровне сети.
REST (5)
Что такое REST?
Архитектурный стиль: данные представлены как ресурсы с URL, взаимодействие идёт через стандартные HTTP-методы.
Разница между GET и POST?
GET читает ресурс. POST отправляет данные в теле и создаёт ресурс.
Могут ли GET-запросы содержать Body?
Нет, согласно спецификации HTTP.
Почему нежелательно отправлять конфиденциальные данные через GET?
В GET данные попадают в URL, поэтому могут утечь через историю браузера, логи, аналитики и кэши.
Разница между path и query?
path определяет ресурс. query передает параметры.
GraphQL (1)
Что такое GraphQL?
Язык запросов и runtime для API, где клиент сам описывает нужные поля и получает их одним ответом.

В чем разница между HTTP и HTTPS?
HTTP передаёт данные без шифрования. HTTPS – это HTTP поверх TLS.
Android Collection: Вопросы на собесе (2)
Разница между ArrayMap и HashMap?
ArrayMap хранит данные в массивах и выигрывает по памяти на небольших наборах. HashMap использует хеш-таблицу, обычно быстрее на средних и больших размерах.
Разница между ArraySet и HashSet?
ArraySet хранит элементы в массивах и экономит память на небольших наборах. HashSet основан на хеш-таблице, обычно быстрее на средних и больших наборах.
Android Build: Вопросы на собесе (20)
Для чего нужен ProGuard?
Используется для оптимизации и минификации кода Android-приложений, а также для защиты от реверс-инжиниринга.
Что такое R8?
Встроенный в Android Gradle Plugin shrinker: удаляет неиспользуемый код, оптимизирует байткод и обфусцирует имена.
Разница между implementation и api?
implementation используется для зависимостей, необходимых только для компиляции, тогда как api позволяет другим модулям видеть эти зависимости.
Зачем нужна обфускация кода?
Обфускация усложняет реверс-инжиниринг: переименовывает классы/методы/поля и запутывает структуру.
Как уменьшить APK?
Применять ProGuard/R8. Удалять неиспользуемые ресурсы. Сжимать изображения. Разделять APK по архитектурам. Использовать Dynamic Delivery. Оптимизировать зависимости.
Что такое Doze Mode?
Doze – режим энергосбережения, когда устройство долго не используется: система резко ограничивает фоновую работу.
Уменьшилась скорость сборки проекта, в чем может быть проблема?
Увеличения числа зависимостей. Использования тяжелых плагинов. Неэффективных задач в Gradle. Отсутствия кэша сборки. Изменений в конфигурациях сборки.
Зачем нужен атрибут targetSdk?
Сообщает Android, под какой API рассчитано приложение, чтобы система применяла новые поведенческие изменения только к тем приложениям, которые на них явно согласились.
Разница между compileSdk и targetSdk?
compileSdk – версия Android SDK, с которой проект компилируется. targetSdk – заявленная целевая версия API, по ней система решает, какие изменения поведения включать.
Что происходит когда пользователь нажимает на иконку приложения и до вызова Application.onCreate?
Система создает новый процесс через форк процесса Zygote, загружает ресурсы и компоненты приложения, создает объект Application, а затем вызывает метод Application.onCreate().
Как происходит форк процесса в Android?
Zygote делает fork() и получает дочерний процесс, который наследует заранее прогретую VM/классы; дальше он инициализирует ActivityThread и подключается к system server через Binder.
Как ускорить холодный старт приложения?
Отложить инициализацию тяжелых ресурсов в Application.onCreate, делать инициализацию ленивой, использовать библиотеку AppStartup, оптимизировать код с помощью ProGuard и R8.
В чем преимущества многомодульности?
Улучшает структуру проекта. Ускоряет сборку. Облегчает повторное использование кода и тестирование. Упрощает управление зависимостями.
Какой путь проделывает сборка от запуска сборки до установки APK?
Запуск сборки. Компиляция кода. Объединение ресурсов. Создание APK. Подпись APK. Установка.
Как код приложения превращается в исходники .dex?
Код Kotlin/Java компилируется в JVM-байткод (.class), затем D8 преобразует его в .dex, после чего .dex кладётся в APK/AAB.
Какие есть приоритеты процессов?
Foreground Process. Visible Process. Service Process. Background Process. Empty Process.
Какие существуют инструменты для отладки и профилирования Android-приложений?
Android Studio Debugger. Logcat. Android Profiler. StrictMode. LeakCanary. Stetho. Firebase Performance Monitoring.
Как настроить CI/CD?
Выбрать инструмент: GitHub Actions, GitLab CI, Travis CI, CircleCI, Jenkins и настроить деплой.
Какой инструмент используется для уменьшения размера APK?
ProGuard

Чем основные компоненты отличаются от других компонентов Android?
Основные компоненты нужно объявлять в манифесте. Также без одного из запущенных компонентов не будет существовать процесс приложения.
Какие из основных компонентов можно не указывать в манифесте?
BroadcastReceiver
Как вызывать основные компоненты?
Activity через startActivity(Intent). Service с помощью startService(Intent) или bindService(). BroadcastReceiver через sendBroadcast(Intent). ContentProvider через ContentResolver.
В каком порядке инициализируются основные компоненты Android?
Сначала инициализируются ContentProvider из манифеста – до Application. Потом в зависимости от Intent, который вызвал старт процесса, создаётся и инициализируется: Activity, Service, BroadcastReceiver.
Context (5)
Что такое Context?
Context – объект, через который компонент получает доступ к ресурсам приложения, системным сервисам и базовым операциям платформы.
Разница между Application Context и Activity Context?
Application Context живет в течение всего времени работы приложения. Activity Context привязан к конкретной Activity и используется для UI-операций.
Какие есть виды Context?
Application Context. Activity Context. Service Context. BroadcastReceiver Context.
Можно ли из Application Context инфлейтить View?
Можно, но обычно не стоит: у applicationContext нет темы конкретной Activity, поэтому стили/атрибуты могут примениться неправильно.
Bundle (6)
Какие типы данных поддерживает Bundle?
Boolean Byte Char CharSequence Double Float Int Long Short String, массивы, Parcelable, Serializable, вложенные Bundle, ArrayList.
Какое ограничение размера у Bundle?
У Bundle нет отдельного лимита, но при передаче через Binder действует предел размера транзакции (порядка ~1 MB).
Почему в Bundle введено ограничение на 1 MB?
Потому что Bundle часто передаётся через Binder: у Binder ограничен размер транзакции.
Почему передавать данные между компонентами рекомендуется через Bundle?
Bundle – стандартный контейнер Android для аргументов и состояния: система умеет его сохранять/восстанавливать при пересоздании компонентов.
Как сохранить в Bundle сложные объекты? (картинки)
Сохрани изображение в файловую систему и храните путь к файлу в Bundle. Либо Base64.
В крэшлитике увидели TransacionTooLargeException. Что будем делать?
Уменьшить объем данных, использовать ViewModel, SharedPreferences или базу данных для хранения.
Parcelable (5)
Почему в Android рекомендуется использовать Parcelable?
Быстрее будет работать в транзакциях между компонентами.
В каких случаях не рекомендуется использовать Parcelable?
Когда не хотим зависеть от Android-специфичных классов.
Разница между Serializable и Parcelable?
Serializable – стандартный интерфейс Java, медленнее, но проще. Parcelable – Android-специфический интерфейс, более эффективен и быстрый.
Что быстрее Serializable или Parcelable по умолчанию?
Parcelable быстрее, так как оптимизирован для Android и избегает рефлексии.
Что быстрее Serializable или Parcelable по режиме ручной настройки?
При ручной настройке Serializable может быть быстрее, но Parcelable обычно остается предпочтительным для Android.
Permissions (8)
Для чего нужны разрешения в Android?
Для контроля доступа приложений к данным и функциям устройства.
Какие виды разрешений бывают в Android?
Обычные разрешения (Normal permissions). Опасные разрешения (Dangerous permissions).
В чем разница между dangerous и normal разрешениями?
dangerous дают доступ к чувствительным данным/действиям, поэтому требуют runtime-разрешение. normal считаются низкорисковыми и выдаются автоматически при установке.
Какие есть способы запросить разрешение в Android?
ActivityCompat.requestPermissions. ContextCompat.checkSelfPermission. launchPermissionRequest в Compose.
Можно ли отозвать полученное разрешение?
Да, пользователь может отозвать полученные разрешения в настройках приложения в любой момент.
Что значит статус show rationale у разрешения?
Означает, что приложение может объяснить пользователю, почему ему необходимо разрешение, прежде чем запрашивать его.
Как работать с локацией в Android?
Использовать FusedLocationProviderClient из Google Play Services, предварительно запросив runtime-разрешения.
Как организовать получение текущей геолокации каждые 10-15 секунд?
Использовать FusedLocationProviderClient с периодическим запросом через requestLocationUpdates.
Notifications (2)
Как группировать уведомления в Android?
Нужно задать общий ключ группы через setGroup(), а сводное уведомление пометить через setGroupSummary().
Для чего нужны каналы в уведомлениях?
Чтобы разделять уведомления по категориям и дать пользователю отдельный контроль над каждой.
Annotations (1)
Разница между @RequiresApi и @TargetApi?
@RequiresApi объявляет минимальный API для элемента. @TargetApi помечает, что код рассчитан на указанный API.

Как научить общаться между собой 2 Android-приложения?
Intent. Content Providers. Broadcasts. Bound Services через AIDL.
Что бы ты улучшил в OS Android?
FindMyDevice. AirDrop. Общий буфер обмена. Нативная реализация без JVM.

Может ли приложение работать в рамках нескольких процессов?
Да, используя атрибут android:process в манифесте для компонентов.
Какие преимущества дает работа в нескольких процессах?
Мультипроцесс даёт изоляцию: падение или утечка в одном процессе меньше влияет на другой.
Какие есть способы сохранения состояния в Android?
onSaveInstanceState. ViewModel. SharedPreferences. DataStore. Room. Files.
Способы безопасного хранения данных в Android?
EncryptedSharedPreferences. SQLite с шифрованием. Файлы с шифрованием. Android Keystore. ContentProvider.
Какие есть виды диплинков?
Стандартные диплинки. Виртуальные диплинки (App Links).
Какой первый класс вызовется при запуске Android-приложения?
Application
В приложении фоторедактора пользователь делает снимок на одном экране. Как передать это изображение на другой экран? Перечислите все возможные подходы.
Bundle-передача через Intent / Navigation Args. Общий in-memory объект. Shared ViewModel / CompositionLocal. Временный файл + FileProvider. MediaStore. База данных / Room. SharedPreferences / DataStore.
Как одного приложения передать изображение в другое приложение, то есть в отдельный процесс Android?
Intent-обмен (ACTION_SEND). Прямой Intent к конкретному компоненту. Временный ContentProvider. ClipData / Drag-and-Drop.
Что такое рефлексия?
Механизм JVM, который во время выполнения позволяет получать информацию о классах, методах и полях, создавать экземпляры, вызывать методы и менять значения полей динамически.
Android Intent: Вопросы на собесе (11)
PendingIntent (2)
Что такое PendingIntent, и в каких случаях его можно использовать?
PendingIntent – объект, который даёт системе или другому приложению право позже выполнить заданный Intent от имени твоего приложения.
Различие между Intent и PendingIntent?
Intent – описание действия и данных для запуска компонента. PendingIntent – обёртка, которая отдаёт право выполнить этот Intent позже.
Другие (9)
Какие существуют типы Intent, и в каких случаях их следует использовать?
Явные Intents: Указывают конкретный компонент. Неявные Intents: Описывают действие, которое нужно выполнить.
Какие данные можно передавать через Intent?
Примитивные типы. Строки. Массивы примитивных типов и строк. Объекты Parcelable или Serializable.
Можно ли передать через Intent массив примитивов?
Да, в Intent можно положить массив примитивных типов.
Как передать данные между Activity с помощью Intent?
Использовать методы putExtra() и getExtra().
Как запустить Activity с использованием Intent, и как вернуть результат обратно в исходную Activity?
Используйте методы startActivityForResult() и setResult().
Как неявный интент понимает какие компоненты могут его обрабатывать?
По intent-filter в манифесте: система сопоставляет action/category/data интента с фильтрами компонентов.
Что произойдет при вызове неявного интента если не будет найдено подходящего приложения?
Система вызовет ActivityNotFoundException.
Можем ли мы запустить компонент другого приложения указав явный интент?
Да, но запуск сработает только если компонент доступен извне (exported=true).
Что такое Intent Filter?
intent-filter описывает, какие неявные интенты может принять компонент.
Android Activity: Вопросы на собесе (35)
Lifecycle (15)
Жизненный цикл Activity?
onCreate() → onStart() → onResume() → onPause() → onStop() → onDestroy()
Какие методы жизненного цикла Activity вызываются при переходе на следующую Activity?
Переходим вперед: onPause() → onStop(). Возвращаемся обратно: onStart() → onResume()
В какой момент жизненного цикла Activity виден экран?
onStart()
Какие методы жизненного цикла Activity вызываются при отображении DialogFragment?
Жизненный цикл не изменяется.
Какие методы жизненного цикла Activity вызываются при отображении/закрытии permission dialog?
onPause() ↔ onResume()
Какие методы жизненного цикла Activity вызываются при переходе в task manager (recent menu)?
Жизненный цикл не изменяется.
Какие методы жизненного цикла Activity вызываются при смахивании приложения?
onPause() → onStop() → onDestroy()
Какие методы жизненного цикла Activity вызываются при сворачивании/разворачивании приложения?
При сворачивании: onPause() → onStop(). При разворачивании: onStart() → onResume()
Какие методы жизненного цикла Activity вызываются при смене ориентации экрана (изменении конфигурации)?
Activity пересоздается: onPause() → onStop() → onDestroy() → onCreate() → onStart() → onResume()
Если запустить Activity2 которая частично перекрывает Activity1, какие коллбэки вызовутся у Activity1?
onPause()
Когда onDestroy вызовется без onPause и onStop?
finish() в onCreate()
В каком случае вызов onDestroy() не гарантирован?
Когда процесс приложения убивается системой или аварийно завершается.
Как изменилось поведение onResume и onPause в Android 10?
В Android 10 в multi-window появился multi-resume: несколько Activity могут быть в RESUMED, а только одна – top-resumed.
Какое состояние будет у 2 приложений, которые отображаются в режиме разделенного экрана?
До Android 10 только та, с которой юзер взаимодействует, получает onResume(). Начиная с Android 10 поддерживается «multi-resume».
В каком из случаев вызов onDestroy() в Activity не гарантирован?
Приложение свернуто, система «убила» процесс приложения. Переворот экрана. Вызов метода finish().
Launch Modes (9)
Какие есть Launch Modes у Activity?
standard singleTop singleTask singleInstance
Для чего нужно задавать параметр launchMode у Activity?
Параметр launchMode задает, как будет вести себя новая Activity при запуске.
Как работает launchMode SingleTop?
singleTop не создаёт новый экземпляр, если Activity уже на вершине стека: интент придёт в текущую через onNewIntent().
Как работает launchMode SingleInstance?
Activity живёт в отдельной task и не делит её с другими Activity.
Есть стек из Activity A-B-C-A-B, запускаем Activity C c launchMode SingleTop, что произойдет в системе?
У Activity C вызовется метод onNewIntent().
Ты находишься внутри Activity A и опять вызываешь Activity A c launch mode SingleTop, что произойдет в Activity A?
Вместо создания нового экземпляра будет переиспользован текущий, и вызовется метод onNewIntent().
Есть Activity А, ты запустил Activity B с launch mode SingleTask и в ней произошел краш, что произойдет с приложением и что увидит юзер?
Приложение завершится, и пользователь увидит системное сообщение о том, что приложение остановилось.
Можно ли стартовать Activity из Application Context?
Да
Эффект какого из launch mode Activity описан ниже?
singleTop

Android Service: Вопросы на собесе (18)
С чем связаны ограничения на запуск сервисов?
Связаны с экономией ресурсов и управления фоновыми задачами.
Какие бывают типы сервисов?
Foreground Service. Background Service. Bound Service.
Зачем сделали Foreground Service?
Нужен для длительной фоновой работы, важной для пользователя.
Как запустить сервис в отдельном процессе?
Указать атрибут android:process в манифесте.
Разница между Service и IntentService?
Service по умолчанию выполняется в главном потоке. IntentService обрабатывает интенты последовательно в фоне.
Что такое Bound-сервис?
Сервис, к которому клиент привязывается через bindService() и получает IBinder.
Разница между обычным Service и Bound Service?
Обычный Service запускают через startService(). Bound Service подключают через bindService().
Как сделать обмен данных между Activity и Service?
Использовать Bound Service, AIDL, BroadcastReceiver, Messenger.
Зачем нужен метод onBind?
onBind() возвращает IBinder – интерфейс для взаимодействия с сервисом.
Какое исключение возникает при долгой работе сервиса?
IllegalStateException или ServiceIntentTooLongException.
Какие есть способы запуска сервисов?
startService(). bindService(). IntentService. JobIntentService.
Жизненный цикл сервиса?
Для обычных: onCreate onStartCommand onDestroy. Для Bound: onCreate onStartCommand onBind onUnbind onDestroy.
На каком потоке вызывается метод Service.onStartCommand?
На главном (UI) потоке приложения.
Как работает межпроцессорная коммуникация в сервисах?
Binder. Messenger. AIDL. ContentProvider.
Есть ли смысл использовать сервис если можно выполнять работу в Application.onCreate?
Да, если работа должна выполняться в фоновом режиме, даже когда приложение закрыто.
Какие есть альтернативы сервисам в Android?
WorkManager. JobScheduler.
Какой из следующих методов используется для запуска сервисов в Android 8.0 и выше?
startForegroundService()

MainThread
Android BroadcastReceiver: Вопросы на собесе (5)
Для чего используется BroadcastReceiver?
Чтобы получать и обрабатывать broadcast-сообщения Intent от системы или приложений.
Какие есть способы регистрации BroadcastReceiver?
Явная регистрация с помощью registerReceiver(). Неявная регистрация путём добавления <receiver> в манифест.
Разница между регистрацией BroadcastReceiver в манифесте и созданием в коде?
В манифесте может срабатывать, когда приложение не запущено; в коде работает только пока зарегистрирован.
Разница между явным и неявным BroadcastReceiver?
Явный broadcast адресован конкретному BroadcastReceiver. Неявный задаёт action/category/data и доставляется всем подходящим ресиверам.
Какие ограничения есть у BroadcastReceiver?
Начиная с Android 7.0 не работают некоторые ACTION. Начиная с Android 8.0 система ограничивает получателей в манифесте.

FragmentManager (15)
Для чего нужен FragmentManager?
Чтобы управлять фрагментами в Activity.
Разница между parentFragmentManager и childFragmentManager?
parentFragmentManager управляет фрагментами внутри Activity. childFragmentManager управляет вложенными фрагментами.
Как работают транзакции у фрагментов?
Транзакция – набор операций над фрагментами. commit() ставит применение в очередь, commitNow() применяет сразу.
Какие методы FragmentManager используются для завершения транзакции?
commit() commitNow() commitAllowingStateLoss() commitNowAllowingStateLoss()
Какие методы завершения транзакции являются синхронными и асинхронными?
Асинхронные – commit() и commitAllowingStateLoss(). Синхронные – commitNow() и commitNowAllowingStateLoss().
Что будет, если мы закоммитить фрагмент, когда приложение свернуто?
Может вызвать IllegalStateException.
Для чего нужен метод commitAllowingStateLoss?
Выполняет транзакцию, даже если состояние Activity потеряно.
Что значит потерянное состояние у фрагмента?
Изменения фрагментов пропадают.
Разница методов add и replace?
add() добавляет новый фрагмент поверх существующего. replace() заменяет текущий фрагмент.
Чем отличается tag в методах add и addToBackStack?
tag в add используется для идентификации фрагмента. addToBackStack создает запись в стек возврата.
Как закрыть сразу n фрагментов в стеке?
popBackStack с флагом POP_BACK_STACK_INCLUSIVE.

LaunchedEffect (7)
Для чего используется LaunchedEffect?
Для запуска корутин, зависящих от изменений входных данных.
В каком потоке запускается LaunchedEffect?
На UI-потоке.
В каких случаях LaunchedEffect перезапускается?
При рекомпозиции и изменении ключа.
Сколько ключей может быть у LaunchedEffect?
Сколько угодно.
Как выполнится LaunchedEffect если в качестве ключа передать Unit?
Запустится один раз при входе composable в композицию.
Разница между LaunchedEffect и SideEffect?
LaunchedEffect запускает корутину. SideEffect выполняет обычный код без корутин.
Разница между rememberCoroutineScope.launch и LaunchedEffect?
rememberCoroutineScope.launch – ручной запуск по событию. LaunchedEffect – автоматический запуск как эффект композиции.

При каждом обновлении key или при удалении компонента.
Вызывается ли метод onDispose при изменении ключа?
Да.

DisposableEffect

Compose UI Components: Вопросы на собесе (9)
LazyColumn (5)
Для чего используется key в LazyColumn?
Чтобы дать элементам стабильный уникальный идентификатор.
Что будет если не задавать ключ в LazyColumn?
Compose будет идентифицировать элементы по позиции, состояние может «переехать».
Какие проблемы могут возникать с LazyColumn?
Пропуск recomposition, перерисовка всей колонки, утечки памяти, проблемы с производительностью.
LazyColumn лагает при прокрутке. Что будем делать?
Оптимизировать элементы, использовать remember, применять key.
Разница между LazyColumn и Column?
Column держит все элементы сразу. LazyColumn создаёт только видимые.
FlowRow (1)
Для чего используется FlowRow?
Раскладывает элементы по строкам и переносит на следующую при нехватке ширины.

Git: Вопросы на собесе (4)
Какие команды есть в Git?
commit branch checkout merge rebase fetch pull push
Как перенести изменения из одной ветки в другую?
git cherry-pick <commit>
Разница между merge и rebase?
merge объединяет ветки отдельным коммитом. rebase переносит коммиты поверх другой ветки.
Разница между fetch и pull?
fetch скачивает изменения не меняя ветку. pull делает fetch и интегрирует изменения.
